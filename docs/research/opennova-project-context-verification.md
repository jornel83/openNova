## M0 技术结论

### 会话与身份

`ctx.sessionController.create({sessionId, cwd})` 是现有公开 API；其内部使用 `ctx.agents.create/resume`，已存在会话会验证持久化目录。`ctx.sessionController.resolveAgent(sessionId)` 可恢复持久会话。OpenNova 使用这些入口，未修改 Harness。

Bot 身份 `bot.id` 保持不变，`bot.sessionId` 指向当前会话。原生 `rt.chatOf(bot.id)` 读取该字段，`rt.save()` 重建当前会话及历史分段的 owner 索引。OpenNova 将每个项目与日常交流的 `sessionId/segments/cwd` 分开保存于 `rt.state.opennovaProjectSessions[bot.id]`，切换时装载对应投影。历史混合会话保留为 `legacy`，不自动作为新项目的历史。

跨项目不使用 `followFolder`。原生目录迁移会生成交接摘要、复制近期消息；这不符合项目上下文隔离要求。同一项目明确更换目录时创建空的新会话，把旧会话登记为该项目的历史分段，保留 `read_own_chat` 检索能力；旧会话自身的 `header.cwd` 不变。

原生同项目自动分段后，宿主在 settle 后调用 `sessions.save()`，把最新 session 与 segments 回写所属项目。单元测试模拟该生命周期；真实自动溢出/压缩尚未在本项集成测试中强制触发。

### 自然话题路由

`createProjectRouter().classify()` 使用独立 `ctx.llm.stream` 调用，输入只有本轮用户文本、有限近期话语、当前/可恢复项目 ID、项目名称与短目标元数据。没有 agent 历史、项目正文、工作页正文或工具结果；`tools: []`，不携带 `sessionId`。

Harness 的公开 `purpose` 当前仅声明 `compaction | session-title`。路由不伪造这些用途，而使用 OpenNova 内部 WeakMap 绑定调用的 messages 对象和活动请求。model gate 校验请求身份、取消状态、固定 provider/model、空工具集与调用 signal；复制、修改或结算后重放分类调用不能继承授权。

模型返回严格 JSON，宿主校验 `focus/projectId` 组合、有效项目 ID、归档状态与同名歧义。非法 JSON、额外字段、未知项目、工具调用和非完整输出转为澄清；模型服务失败或超时同样澄清，不提交焦点变更。用户取消保持取消语义，不执行路由结果。

明确恢复已归档项目使用受限的 `focus:manage/action:restore` 意图，普通工作仍不可绑定归档项目。管理会话使用独立的中立目录与会话映射，不加载被归档项目的工作历史。宿主只允许恢复指定项目的管理操作，完成后恢复原选择。创建项目可使用现有活跃项目作为管理入口；全部项目均已归档时，先恢复项目或从项目面板创建。

项目会话接入 model gate 后，普通前台流必须来自当前已绑定的 work/daily/manage 请求及当前会话。已离开的项目会话不能借用另一请求的准入；维护调用限定在当前项目的会话/历史分段。这个逻辑边界不改变 Full Access 文件权限。
