# OpenNova 团队 M3：运行稳定性与交付验收

2026-11-07。沿用团队版 M1 / M2 的单机串行队列、独立员工会话和总管验收。M3 补充运行状态、组合故障验证、长时间观察和恢复工具，保持现有语音、对话及极简任务面板入口。

## 运行状态

任务执行记录显示当前阶段和最近活动时间：准备工作会话、等待前台对话、等待模型、执行工具、衔接步骤和运行命令。总管验收期间在成果区域显示对应管理轮次的活动。

`activity.json` 绑定 Task / Run；模型输出和工具事件更新真实活动时间，5 秒心跳单独记录。心跳证明运行时事件循环仍响应，不代表模型有新进展。状态长时间没有更新只提示无法确认，不判定失败、不重放操作、不增加隐式执行时限。历史 Run 和终态覆盖旧活动记录，用户看到的活动不会串到另一任务或成果版本。

遥测文件损坏或写入失败不阻断任务详情及执行。原子写入失败清理本次临时文件，避免默认无限预算下重复心跳造成临时文件累积。单轮和累计预算继续默认不限制；手动上限、自动返工次数、事件接续次数与暂停取消规则继续独立生效。

## 宿主重启后的网页重连

浏览器验收复现了多标签页竞争：重启后一个页面刷新共享 Cookie，另一个页面仍保留旧 CSRF，原先只恢复 401 而持续收到 403。API 与事件连接现在仅对明确的会话认证失败刷新并重试一次，普通操作权限错误不会重试。真实 HTTP 双页面回归验证副作用操作只进入处理器一次。

## 历史任务调度性能

预检使用成功离线团队流程的合法历史副本，每组含 5 个 Task、6 个 Run 和 4 份报告。在同一机器的隔离 SQLite 上测量中位耗时：

| 历史组数 / Task 数 | 总管空闲 tick：原 → 修复后 | 完整调度 tick：原 → 修复后 |
| --- | --- | --- |
| 100 / 500 | 79 → 4 ms | 101 → 28 ms |
| 500 / 2,500 | 2,277 → 23 ms | 2,400 → 148 ms |
| 1,000 / 5,000 | 9,198 → 44 ms | 9,527 → 286 ms |

修复为成果和验收 JSON 字段增加查询索引，已处理报告按 Task / Run / 派工版本 / reportId 精确跳过重复读取；同一 Run 重新生成报告仍须独立验收。当前页面与下游交接仍检查文件状态，没有跨轮缓存掩盖成果变化。8 小时计划负载约 480 组，500 组完整调度耗时低于当前 250 ms 间隔。5,000 个 Task 时仍有 TaskManager 全历史遍历带来的线性开销；后续扩大规模需按活动状态筛选执行记录，本轮不宣称无限历史规模下性能恒定。
