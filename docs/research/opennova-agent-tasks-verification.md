# OpenNova 后台任务第二阶段

2026-11-05。第二阶段在现有 Task / Run / Job 上增加独立 Agent 工作会话，不引入 super agent prototype，也不实现第三阶段事件触发。

## 使用

右侧窗口进入“任务 → 新建 Agent 工作任务”，填写目标、约束、工作模式和预算。只读分析提供文件查找、搜索与读取；修改并验证模式另外提供文件修改和受监督命令。也可以说“在后台分析这个工程”或“创建后台任务修改某个功能并验证”。提交后主对话继续可用。

详情显示每次 Run、真实工具步骤、命令退出码与日志（展开命令步骤可实时读取）、模型步骤、Token 用量和本轮报告。正常结束只表示 Agent 本轮结束，不能替代测试通过的证据；测试失败仍会显示对应命令退出码。

运行中可以保存补充要求。要求先持久保存，在当前 Harness 轮次结束后提交；接近结束时才到达的消息保留为待处理，可显式接续。需要立即改变正在进行的操作，应先暂停。状态区分待处理、已接收和接收情况待核对；已接收表示进入模型会话，不承诺当前操作已按新要求完成。状态不明的消息不会由 OpenNova 自动重发。

暂停、取消停止模型及工具，并保留文件和会话。回答任务提问或点击“接续任务”，沿用同一个 Task、会话和工作目录，创建新 Run。任务完成后也能接着修改。宿主重启恢复列表、记录和日志，已经启动的 Run 不自动重跑；未启动的队列仍按顺序执行。清理回执不明确时阻止后续执行，避免旧作业仍在写文件。

修改任务停止后，点击“查看文件差异”，审阅后点击“应用到原工程”。只应用已查看的版本；原工程受影响文件已变化则拒绝覆盖。支持文本、普通二进制文件、增加、删除和可执行位变化，保留原工程暂存区；符号链接、子模块等特殊文件需手动审阅处理。应用成功后更新差异基线，后续 Run 可以增量应用。应用过程中崩溃留下的未知回执需要人工核对，不盲目重放。

## 隔离与运行边界

后台 Agent 需要当前目录是已有提交的 Git 工程根目录。每个 Task 在仓库外创建独立 Git worktree，启动快照包含当前受版本管理文件和未被忽略的新文件，既有暂存区不变。忽略的授权配置、依赖目录和构建产物不会复制；Agent 根据任务自行检查和准备依赖。不会自动提交、推送或合并分支。任务分支名为 `codex/task-*`，工作区和未应用修改保留供检查，当前不自动清理。

worktree 用于代码协作隔离，**不是操作系统沙箱**。普通文件工具限制在任务工作区；命令仍具有当前用户权限，须以前台进程运行，不支持守护化或主动脱离进程组。命令环境移除常见凭据变量。全局安装、部署或修改外部配置不属于本阶段默认任务范围。

后台 Agent 和命令共用一个串行队列。前台 Bot 使用原进程和会话，后台每个 Run 使用独立 Harness 进程；新的后台模型步骤会等待前台空闲。已经发出的后台模型请求不会被前台抢占。每轮模型步骤、Token 和运行时间默认不限制；创建页预算字段留空即可，填写后按上限执行。旧任务保留创建时的有限预算。Token 优先依据服务端报告累计；当前 SIWC 结构化适配未提供用量时，使用 Harness 的文本与工具估算，并在面板标注“估算”。下一步骤前也估算输入并检查余额。该预算是执行限额，不能作为计费数字，也不能保证单次响应恰好停在预算值。单个任务命令最长 10 分钟，每份命令日志最多保存 8 MiB。

授权、Bot、记忆、任务数据库、会话、日志和工作区均沿用仓库外数据目录。没有迁移或覆盖日常配置，没有把测试对话放入日常 Bot。

## 实现位置

- `services/bot/tasks/manager.mjs`：Task / Run / 主 Job 与补充消息的 SQLite 记录、队列、暂停接续、结果协调、差异和应用接口。
- `agent-runner.mjs`：每轮独立 SDK 进程、补充要求交付和报告。
- `agent-runtime.mjs`：单任务私有文本 SDK 适配，使用公开 `agents.create/resume` 恢复持久会话；上游 SDK 默认只新建会话，因此在 OpenNova 插件层完成适配。仍通过 `dsh --profile sdk-minimal` 启动，不修改上游核心循环。
- `agent-plugin.mjs`：文件范围检查、分析模式、真实工具步骤、受监督 `task_command`、等待用户的 `task_question`、预算和前台优先。
- `workspace.mjs`：工作目录快照、差异版本、冲突检查、幂等应用回执和增量基线。
- `agent-files.mjs`：原子 JSON 存储。工具步骤、补充交付账本及进度是仓库外文件；Task / Run / 主 Job 和消息在 SQLite 中。
- `services/bot/web/agent-tasks.jsx`：创建表单、步骤、补充和接续、报告与差异操作；现有命令任务界面保留。

模型工具增加 `background_agent_start/message/pause/continue/diff/apply`。网页新增 `/web/api/background-task-message`、`-pause`、`-continue`、`-diff`、`-apply`，沿用同源、Cookie 和 CSRF 校验。后台前台协调使用仅 Bearer 可访问的 `/background-task-admission`。网页应用差异与前台文件操作互斥。

## 验证

离线测试启动真实 bundled Harness，仅替换模型服务，覆盖原生读写、实际测试命令、文件隔离、会话跨 Run 与宿主重启恢复、暂停后命令退出、规则插件加载失败时拒绝启动、无服务端用量时的预算限制、提问接续、运行中补充要求、只读模式、步骤预算、异常命令不阻塞队列、重复提交、脏工作区快照、二进制文件应用、多轮增量应用、冲突和过期差异拒绝、工作区创建恢复。宿主集成测试还覆盖自然语言工具提交、后台工作时前台请求可用、暂停和重启接续。

真实模型在临时工程与独立 Bot 中通过自然语言提交任务，读取并修改 `sample.txt`，运行 Node 严格断言，真实退出码为 0；同时前台聊天成功，原工程文件未变。随后接续同一任务，准确复述此前修改和退出码。证据在本机忽略目录 `output/agent-tasks/real-evidence.json`。

完整 `pnpm test`：444 项 Node 和 186 项 Python，共 630 项通过。后续边界修正另经针对性测试；命令与日志在 `output/agent-tasks/`。浏览器验收与最终启动结果见本文件末尾记录。
