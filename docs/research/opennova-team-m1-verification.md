# OpenNova 团队版 M1 实现与验证

2026-11-06。M1 已交付员工目录、任务归属、身份校验、独立资料工作区和基础团队面板。总管自动验收、有限返工、改派与依赖、待决策管理属于 M2；晨会不在第一版范围。

现有主 Bot 保持原身份。用户可以进入右侧窗口的“任务”页，添加员工、编辑职责和可承接工作，按负责人筛选任务。新建 Agent 工作任务可选择代码工程或本地资料整理，并指定负责人；后台命令默认由总管负责，也可指定具备命令能力的员工。即时请求仍由前台助手直接处理。

## 实现

- `services/bot/team/registry.mjs` 适配原 Bot 员工目录，用外部 SQLite 的 `team_record` 保存工作配置与可恢复的创建操作。身份和职责仍由 Bot 维护；总管身份不重建。无工作配置的其他 Bot 默认不启用，避免部分创建意外获得执行能力。
- `team/actor.mjs` 提供宿主签发的调用身份及当前 Run 校验。后台管理身份不依赖前台请求；M1 只建立此准入能力，自动总管管理会话在 M2 接入。模型参数中的身份不会直接赋予权限。
- `team/tools.mjs` 提供团队查询和用户要求下的员工管理；任务路由通过产品指令、现有后台任务工具和服务端 assignment 校验实现。未引入第二套消息派工执行循环。
- Task 保存 assignedBotId、supervisorBotId、reportTo、assignmentVersion、routing 和来源；每轮 Run 保存当时的角色及必要记忆快照。员工改名后列表显示新名字，历史执行快照保持原样。旧任务以兼容视图显示原总管，不重写旧 Run。
- `tasks/documents.mjs` 将明确指定的项目内文本资料复制到外部任务目录，最多 10 个文件、每个 64 KiB；排除凭据名称、隐藏目录、越界路径和符号链接。资料任务提供文件工具，禁用 Shell 和异步检查工具，不应用到原工程。输出文件在结果区域展示。
- 团队面板使用现有认证入口、事件通道和快照更新。员工有未完成任务时不能停用，团队有员工未完成任务时不能关闭派工。停用不删除会话、记忆或任务文件；M1 不提供员工删除或任务改派。

后台继续串行执行。角色的可承接类型限于代码、资料和命令，工作范围限定为当前工程与其任务目录。员工名字和职责不会自动开放额外 MCP、浏览器或联网工具。代码任务的 worktree 仍是协作隔离，不是操作系统沙箱。

## 验证结果

| 验证 | 结果 |
| --- | --- |
| 完整产品回归 | 467 项 Node 测试和 186 项 Python 测试通过，共 653 项 |
| 上游 Bot 回归 | 517 项通过 |
| 团队测试 | 6 项目录、身份、记忆与路径测试，加 1 项真实 Bot / Harness 宿主集成测试通过 |
| 界面 | 460 × 900 窗口完成创建员工、指定负责人、提交资料任务、查看职责与结果、筛选和刷新恢复；页面宽度 460，无横向溢出，控制台 0 错误、0 警告 |
| 构建与源码 | 完整构建通过；doctor 的 build.ready 为 true；源码审计 independent 为 true、gitlinks 为 0 |

集成测试验证创建在 Bot 保存后、SQLite 回执前中断可以恢复，不重复创建员工；无效姓名和重名请求不会留下阻塞启动的操作记录；伪造身份、过期 Run、跨员工访问和不支持的任务类型被拒绝；任务上下文只包含自身与团队记忆；职责更新后历史快照保留，重启后沿用任务会话接续。

真实模型在隔离 Bot 和临时工程中验证了三条路径：

1. 总管即时回复“你好”，未创建后台任务。
2. 总管负责后台执行 `node -e "console.log(42)"`，真实退出码为 0。
3. 按自然语言要求将 `sample.txt` 交给“资料员”，主助手查询并指定员工，将任务提交到资料工作区。员工完成文件查找、读取、写入和回读，生成 `report.md`；任务负责人为资料员，退出码为 0。

首次真实模型调用因进程未使用系统代理返回 network_error。使用机器已配置的 `127.0.0.1:7897` 代理重试后上述验证完成；没有修改系统代理设置或授权账号。
