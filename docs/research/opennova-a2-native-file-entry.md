# A2 两个文件入口：原生读取接入记录

日期：2026-11-16。范围：前台文件读取首批交付，对应 [A2 计划](../superpowers/plans/2026-11-16-a2-research-learning.md) 的 M0 与 M1 前台部分。源码和构建位于原工程目录，不是先前 A1 的独立 worktree。

2026-11-18 更新：前台 `document_read` 增加 PDF 物理页范围和超时后有限恢复，见第 5 节。第 1–4 节记录首次交付时的行为和验证环境。

## 1. 已接通的行为

- **直接说文件名或路径**：例如“读一下项目里的语音方案.pdf”。文件名在当前项目目录及全部已关联文件资料中定位；不同路径同名时返回候选，请用户明确。支持绝对路径、相对项目路径及 `~/`，沿用现有文件访问权限。名称查找不进行全盘索引，跳过 `.git`、`node_modules`、`output`、构建和依赖目录；超过 10000 项或目录不可访问时报告查找不完整，用户可补具体路径。
- **引用当前文件**：例如“解释一下这份文件”。说“Nova 刚才读的那份”使用发送时的项目关联。说“我正在 WPS 里打开的 PDF”使用 macOS 文档窗口，文字和语音共用同一读取入口。有多个可能的文件、窗口未提供身份或权限不足时，工具会请用户明确目标。读的是已保存的磁盘版本。同一轮刚打开的新文件用打开回执中的实际路径读取，不替换发送时的指代。
- 成功读取后显示当前文件及按本次问题读取的状态；操作记录可查看内容、文件路径、内容哈希和限制。项目资料页显示可按需读取，不把关联或打开当作已读正文。读取一次不会自动加入长期项目资料。
- 已接入 PDF、PNG/JPEG/WebP、DOCX、XLSX，模型附件上限 **20 MiB**（前台按页段读取的本地 PDF 原件最多 64 MiB）；TXT/Markdown/代码等继续使用既有 `read`。实际样本覆盖范围见下表，不能从扩展名支持推断任意文件均能可靠读取。

## 2. 实现与版本约束

链路为 `/ask → 本轮项目/对象绑定 → 主模型选择 document_read → 稳定文件快照 → 同一模型原生附件读取 → 有来源的工具结果 → 主对话回答`。

当前 Harness 将 FileBlock 转为路径句柄。因此在 OpenNova 层新增 `document_read`，工具内使用当前授权的 `gpt-6.1-sol`，PDF/Office 传 `input_file`，图片传 `input_image`。**主会话收到读取文本和来源，并非直接携带原文件附件**；主 provider 继续声明文本输入，上游 Harness 无修改，也不新增解析/OCR 依赖。每次新读取额外产生一次独立附件模型调用；读取器无工具执行权限，文件内指令只能作为资料。

读取前后检查文件大小、mtime、ctime、inode；保存真实字节 SHA-256、项目、请求和内容来源。私有快照保存在当前 Bot 数据目录的 `file-inputs/`，使用现有操作记录持久保存读取内容及来源；不会因轮次结束自动删除。相同字节复用快照，长期留存/清理界面后续由 D3 处理。

当前引用或关联资料的版本过期时先返回变化；明确重读可用实际路径读取新版本。模型处理期间原文件发生变化，仍以已固定的快照为依据并标明磁盘已变化。后续 `write/edit` 也检查该已读版本，拒绝覆盖外部新修改。取消、切项目、迟到响应不能发布成功或抢占新选择的对象。

已完成结果随工具历史保存，重启和回放不自动重读原路径；需要补读时再次调用。中断读取标为 interrupted，不自动重放。部分可读、无法读取、错误、超时与取消分别记录；原生读取器单次限时 90 秒。加密或损坏可能表现为 unreadable、partial 或安全错误，尚未保证细分每种格式问题。

## 5. 2026-11-18：PDF 读取范围与稳定性

例如“解释这份 PDF 第 3 至 5 页”。`document_read` 仍使用文件名／路径或当前文件；新增可选的 `startPage`、`endPage` 是一组从 1 开始、包含两端的原文件物理页码。工具固定原文件快照，在本机用 Swift/PDFKit 提取真实页段，仅提交选中页的 PDF 字节。回执和当前文件保留原路径、原件版本和原页码，不把派生附件绑定成当前文件。

| 请求或结果 | 实际行为 |
| --- | --- |
| 单页或连续页段 | 单页使用相同的起止页。最多一次选 256 页；显式选页时前台原件最多 64 MiB，派生 PDF 最多 20 MiB。越界、损坏、加密或裁剪不可用时明确失败，不自动退回提交整份。页号指文件物理顺序，可能与印在页面上的编号不同。 |
| 只给问题或章节名 | 没有已知页段时，仍将原附件传入模型；问题限定回答目标。未实现按章节标题自动定位，也不把某一范围被送入模型等同于其中所有内容已经核实。 |
| 原生附件请求 | 记录构造附件、取得客户端、模型往返和解析回执各阶段耗时。一次原生调用仍限 90 秒；“模型往返”包括传输和等待，不能凭这一项判断服务端推理耗时。诊断不保存提示词或文件内容。 |
| PDF 的模型请求超时 | 多页请求至多再试一次：从本次范围起点截取较短页段，最多 3 页。缩小范围后有结果，状态仍为 `partial`，记录真正提交的页段及待续页；失败、单页超时、用户取消不伪装成已读。第二次调用也有自己的 90 秒上限。 |
| 显示与续读 | 文件卡片显示原文页段，操作记录区分已确认内容、失败和可续读范围。后续可指定剩余页段继续；当前文件已变化时仍执行版本检查。源 PDF、已生成成果和其他项目的当前对象保持原样。 |

| 提问方式 | 运行时结果 | 独立核对 |

## 在 macOS 上引用正在看的文档

在目标文档窗口中看过内容后，直接切回 Nova，或在文档仍在前台时通过语音提问。例如「读一下我正在 WPS 里看的 PDF 第 1 到第 3 页」。宿主在发送时确定目标，模型开始回答前切换到另一个窗口，不会更换本次输入。成功的工具回执会显示实际文件和窗口来源。没有引用桌面文件的对话不会把桌面路径写入该请求的模型提示或记录。

支持提供本地文档路径的窗口。对于 macOS 版 WPS 只提供窗口标题的情况，额外核对该应用实际打开的文件与磁盘文件身份；同名歧义、窗口关闭或权限不足时需要澄清。若 macOS 禁止读取窗口信息，可在「系统设置 → 隐私与安全性 → 辅助功能」中检查启动 OpenNova 的应用，或直接在对话中给出路径。后台研究任务继续使用提交时明确选择的输入文件。
