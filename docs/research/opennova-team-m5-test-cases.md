# OpenNova 团队 M5 人工测试用例

本轮验证技能发现、员工绑定、经验提炼、版本管理与已有视频技能复用。入口仍为右侧窗口的“任务”页，不增加主导航；语音和原对话框继续用于派工、补充要求与询问进度。

建议先用专门的测试员工和 `M5-` 开头的任务，避免修改正在使用的员工技能。记下测试前的员工绑定、技能状态和经验沉淀设置，结束后按需恢复。沿用已有启动方式及蓝牙设备配置；授权、会话、记忆、技能版本和测试任务数据继续保存在仓库外。

## TC1：找到内置技能

1. 打开“任务 → 技能库”。
2. 找到 `video-production`，检查适用场景、启用状态、版本短标识。
3. 点击“版本记录”，确认能查看当前版本；返回后刷新页面，再打开技能库。

预期：内置技能可见、刷新后保留。不需要复制一份新的视频工程，也不会因为打开技能库而提交视频生成。版本短标识用于辨认内容，不是递增的版本号。

## TC2：检查自动沉淀的默认设置

1. 打开“技能库 → 经验沉淀设置”。
2. 检查“验收通过后自动整理经验候选”和“允许自动启用符合条件的新技能”。

预期：首次使用默认开启自动整理候选，默认关闭自动启用。已有用户保存的设置应保留；看到之前修改过的状态不算回归失败。生成候选只是在整理方法，技能需按后续用例保存才能进入可用技能库。不要为本次测试开启自动启用。

## TC3：员工绑定与任务选择

1. 打开“任务 → 管理员工”，新建或选择测试员工。
2. 在该员工卡片展开“技能配置”，勾选 `video-production`，点击“保存技能配置”。
3. 刷新页面，确认绑定保留。
4. 打开“新建 Agent 工作任务”，负责人选择这位员工，展开“使用技能”。
5. 检查“按任务自动匹配”“指定技能”“本次不使用技能”三个选项。选择“指定技能”，检查只列出这位员工可用的技能。
6. 不勾选技能时，“提交 Agent 任务”应不可用。勾选 `video-production` 后恢复可提交。

可以提交以下不产生付费生成的只读任务：

> 任务名：M5-视频技能只读检查。读取 video-production 技能和它引用的工具约定，说明适用场景、所需输入、如何等待和下载结果。不要提交远端生成，不要运行付费请求，不修改任何文件。

执行权限选择“只读”。预期：任务详情出现“本轮使用技能”，显示技能名与固定版本；执行记录可以核对技能读取。技能绑定不会把只读任务提升为完整执行权限。

自动匹配表示把员工已绑定且启用的技能提供给任务，由模型根据目标判断是否使用；不代表每个任务都会调用所有技能。“本次不使用技能”是明确不提供技能的方法，不会取消员工长期绑定。

## TC4：完成一次可沉淀的工作

给测试员工派以下通用任务，执行权限使用“完整执行”，开启“由总管检查成果并跟进”，本次技能选择“本次不使用技能”：

> 任务名：M5-金额汇总原任务。在独立任务目录创建 ledger.csv，内容为 item,amount 表头，以及 A,10.50 和 B,20.25 两行数据。读取 CSV 的 amount 列，用 Decimal 求和，保留两位小数；生成 summary.md，写明行数为 2、合计为 30.75。实际执行检查命令核对输入和报告，保持输入文件不变。将 summary.md 作为成果交付。

预期：执行完成且总管验收通过；成果文件可打开，内容为两行数据、合计 30.75，实际检查退出码为 0。仅“执行完成”不足以触发已验收经验提炼。

若自动整理开启，展开成果卡“复用这次工作方法”，应先显示正在整理，再出现候选及“保存为技能”。模型生成速度受网络和模型响应影响，不以固定秒数判断失败。若自动整理关闭，点击“整理为技能”显式触发即可；原业务任务不会重新执行。

## TC5：检查候选并保存

1. 在上述成果卡“复用这次工作方法”中点击“保存为技能”。
2. 将名称改为尚未使用的 `m5-csv-sum-demo`，检查“适用场景”和“工作方法”。
3. 方法应说明输入 CSV、amount 列、Decimal 求和、输出位置、检查办法和适用边界；输入输出应参数化，不将本次的具体金额、个人绝对路径或凭据当成以后固定步骤。
4. 保持“保存后启用”勾选，点击“保存技能”。
5. 返回技能库，检查新技能已出现，候选显示已保存。

预期：只有整理完成的候选能保存；正在整理时不能提前启用。保存是明确的用户操作，与 TC2 的“自动启用”开关不同。保存同名技能会明确提示产生新版本，旧版本保留；不要用测试候选覆盖其他业务技能。

如果显示整理失败，页面应提供原因和“重新整理”。重试只重新提炼经验，不重新执行原业务任务；原任务的执行记录数量应保持不变。来源成果被修改、任务关闭或验收失效时，旧候选不能继续直接启用。

## TC6：换一组输入复用技能

1. 在“管理员工 → 测试员工 → 技能配置”确认 `m5-csv-sum-demo` 已默认绑定。启用后的经验技能会自动提供给总管及来源员工，原有技能绑定应保留；仅在之前未启用、手动取消过绑定或同步提示要求重新确认时，再选择并保存。
2. 新建通用任务，负责人选择同一员工，在“使用技能 → 指定技能”勾选该技能。
3. 提交以下要求，并开启总管检查：

> 任务名：M5-金额汇总复用。使用 m5-csv-sum-demo 的方法处理新数据。在独立任务目录创建 ledger.csv，表头 item,amount，数据 C,4.10 和 D,5.20。生成 summary.md，报告行数和合计，实际执行检查。不得照抄之前任务的合计。

预期：结果是行数 2、合计 9.30，经过本次真实检查和验收；任务详情显示所用技能版本。技能提供工作方法，不能把旧成果直接当作本次交付。执行步骤应能够核对技能读取与本次文件、命令操作。

## TC7：更新、回退、停用与刷新

1. 记下 TC6 任务详情的技能版本短标识。
2. 在技能库对 `m5-csv-sum-demo` 点击“更新内容”，修改适用场景或方法，保存。
3. 点击“版本记录”，检查有新旧两版，新版标记为当前。
4. 返回 TC6 历史任务；它仍应显示创建执行时保存的旧版本。
5. 返回版本记录，对旧版点击“使用此版本”，确认技能库切回旧版。
6. 点击“停用”，检查技能显示已停用；员工长期绑定仍保留，新任务不再自动选用。随后重新“启用”。
7. 刷新页面，确认启用状态、回退后的版本、员工绑定和历史任务记录均保留。

预期：技能库变更不会替换已有执行轮的版本；接续原任务沿用已保存的技能上下文，新任务使用当前可用版本。停用不会删除旧成果或任务历史。

如果看到“设置已保存，正在同步到员工”，等待后台重试即可，不需要重跑业务任务。如果提示同步需要重新确认，先刷新，检查员工是否启用、技能是否启用，再重新选择并保存员工技能。如果提示技能无法载入，应检查其文件和资源完整性。

## TC8：对话与语音保持原入口

可以通过原对话框或语音说：

> 看看有哪些技能，金额资料员可以用哪些？

> 把 M5-金额汇总复用这次已经验收的工作方法整理为技能，先给我候选，不要自动启用。

预期：总管先查询真实技能或任务状态，定位明确的员工、任务和成果；有重名时需明确对象。通过原入口能够完成查询、提炼或用户明确要求的保存/绑定，不新增单独的“回复员工”界面。若目标成果已提炼，应复用既有候选而不重复执行原业务任务。

## TC9：视频等待与交付的人工验收

本项按用户 2026-11-08 的选择留待后续配置凭据后执行。本轮先完成本地与模拟验收，不将本项计为已通过。

这项需要已配置的视频服务凭据和实际生成额度。只有准备执行一次真实视频测试时再提交；前面的只读检查不需要视频生成费用。

1. 给测试员工绑定 `video-production`，创建明确选择该技能的完整执行任务，写清短片内容、时长、比例与交付要求。
2. 示例要求：

> 制作一段 4 秒、16:9 的清晨海边风景短片。使用 video-production，先核对参数，再提交一次远端生成；等待同一个远端任务完成，下载本地视频并验证文件可播放。交付视频文件和简短说明，不重复提交相同生成。

3. 检查详情中的“视频制作进度”：远端任务编号、排队/生成/完成状态应可追踪。等待期间能继续聊天，也能执行另一个简单任务。
4. 生成完成后检查下载文件和实际执行记录，手动播放，核对画面、时长、比例及是否符合要求；不能仅凭“生成完成”判断已下载或已验收。
5. 如选择停止本地跟进，页面应明确说明这不代表远端生成已取消。不要因等待较久而重新提交同一生成。

离线 fixture 已验证真实本地调度、同一远端编号等待、重启接续、下载和交付链路；远端响应与视频素材由测试替身提供。它不能证明当前账号额度、第三方服务网络、真实生成画质或收费请求通过。没有真实付费生成与人工播放结果时，本项仍为待人工验收。

## TC10：结束与结果记录

记录每项通过/失败、任务名、技能版本及可复现的错误。无需提供凭据、授权文件或完整私人对话。测试任务不再继续时，可使用原“关闭任务”移出默认列表，历史与成果保留；测试技能可停用，员工配置可恢复到测试前状态。

本轮短时浏览器检查不能替代 8 小时耐久测试。长期运行验收另见 [团队长时间运行验证](opennova-team-soak.md)，没有完整完成报告就不能计为通过。
