**2026-11-12 状态更新。** TC4–TC6 已有真实任务记录，TC8 已获用户确认，TC3/A3 已经实际执行和日志复核通过；软件、真实模型及真人证据见 TC10，不要求全部重测。夜间长测已完成实际 8 小时观察，但因源码在运行中变化而失败，不能计为稳定性验收通过。需冻结修复后的版本、回归并重新构建后另行安排；本次未自动重跑。

## 测试前准备

1. 沿用当前启动方式，不需要重启正在运行的日常实例。Mac 声音输入选择 **MacBook Air 麦克风**，输出选择 **MacBook Air 扬声器**。先用对话框测试，再用相同要求做语音测试，便于区分业务与转写问题。
2. 打开“任务 → 管理员工”，新增固定名称 **M5验收员**，职员名称填“技能验收专员”，工作要求填“按任务要求执行并核对成果，保留实际执行证据”，保持“允许承接任务”勾选。同名测试员工已存在时直接复用，不重复创建。
3. 记录原来的员工绑定、技能状态和经验沉淀设置。所有测试任务用 `M5-` 开头，不改日常任务或业务技能。
4. 除特别说明外，新建任务统一选择：负责人 **M5验收员**、模板 **通用工作（默认）**、权限 **完整执行（Full Access，默认）**；勾选“自动检查成果并跟进”；“执行预算”保持“不限制”（三个输入框留空）；**不勾选“测试完成后自动接续”**。输入文件留空。
5. 下文任务名填入“任务名称”，代码块填入“任务目标”。重复测试时在任务名和技能名末尾加 `-2` 等后缀，并同步替换后续引用。

授权、会话、记忆、技能版本和任务数据继续放在仓库外。这组测试调用真实模型，语音还使用当前语音服务与额度。本地视频不需要火山方舟凭据，不提交付费视频生成，**不代表整个 OpenNova 可以脱网运行**。

## TC1：找到内置技能

1. 打开“任务 → 技能库”，找到 `video-production`。
2. 检查适用场景、启用状态和版本短标识，点击“版本记录”。
3. 刷新页面，再打开技能库。

预期：技能、当前版本和状态保留；查看技能不会提交视频生成。版本短标识用于辨认内容，不是递增版本号。当前若已停用，先记下状态，再为本次测试启用，结束后恢复。

## TC2：检查自动沉淀的默认设置

1. 打开“技能库 → 经验沉淀设置”。
2. 检查“验收通过后自动整理经验候选”和“允许自动启用符合条件的新技能”。
3. 为方便后续测试，将前者开启、后者关闭，点击“保存沉淀设置”。原状态不同则记下，结束后恢复。

预期：首次使用默认自动整理候选、默认不自动启用；已保存的用户设置应保留，之前改过的状态不算失败。生成候选不代表已保存或启用技能。

## TC3：员工绑定与任务选择

1. 打开“任务 → 管理员工 → M5验收员”，展开“技能配置”，勾选 `video-production`，点击“保存技能配置”。刷新后确认绑定保留。
2. 打开“新建 Agent 工作任务”，负责人选 M5验收员，展开“使用技能”。
3. 检查“按任务自动匹配”“指定技能”“本次不使用技能”三个选项。选“指定技能”后只应列出该员工可用技能。
4. 不勾选技能时，“提交 Agent 任务”不可用；勾选 `video-production` 后可提交。
5. 在“执行权限”中选择“只读”（不是默认的完整执行），新建独立任务，提交以下目标。此项不需要视频生成凭据。

任务名：`M5-视频技能只读检查`

```text
先调用 skill 加载 video-production，再读取它引用的工具约定，说明适用场景、所需输入、如何等待和下载结果。只做说明，不提交远端生成，不调用付费请求，不运行命令，不修改文件。
```

预期：“本轮使用技能”显示技能名和固定版本；“执行步骤”能找到成功的 `skill` 调用，以及 `read` 读取引用文件的记录。回复能说明技能用途、输入和等待/下载步骤；没有写文件、命令或远端生成记录，技能不会把只读权限提升为完整执行。只读不提供任何 `video_*` 工具（包括 `video_validate`），此用例只读取约定，不要求调用它们。

**注意：**“本轮使用技能”只表示本轮提供了哪些技能版本，不能证明实际加载。是否加载必须看 `skill` 调用。自动匹配是提供员工已绑定且启用的技能，由模型按目标选择，不保证每项都加载；“本次不使用技能”不会取消员工长期绑定。

## TC4：完成一次可沉淀的工作

创建任务时选择 **M5验收员**，保持“自动检查成果并跟进”开启；技能选“本次不使用技能”，其他选项沿用前面的默认设置。

2026-11-09 起也可选择“总管负责”验证同一流程：总管亲自执行后，另建独立只读验收会话，核对实际文件和执行证据，符合要求自动通过。员工执行与总管自执行都保留开关，关闭后才等待人工验收。旧任务保留原设置；已完成但未验收的旧任务可在详情“总管跟进”中打开“启用成果检查与跟进”，先检查现有成果，无须重新提交原任务。检查发现可修正问题时仍可能按原范围返工。来源为总管的经验技能保存后默认绑定总管，后续交给 M5验收员复用时需另行给该员工绑定。

任务名：`M5-金额汇总原任务`

```text
在独立任务目录先创建 ledger.csv，UTF-8 内容严格为以下三行（1 行表头、2 行数据）：
item,amount
A,10.50
B,20.25

创建完成后不再改动 ledger.csv。读取 amount 列，用 Decimal 求和，保留两位小数；生成 summary.md，内容严格为以下两行，不加标题、代码围栏、空行或其他说明：
行数：2
合计：30.75

实际执行检查命令，核对 CSV 表头和两行原始数据、数据行数、Decimal 合计及报告两行内容，检查须退出码为 0。交付 summary.md；检查过程和结果写在汇报里，不追加到 summary.md。
```

预期：执行完成且总管验收通过；打开 `summary.md`，严格为：

```text
行数：2
合计：30.75
```

“实际执行证据”或“执行步骤”有本次检查命令和退出码 0。CSV 数据行数不含表头，不能算成 3。

验收通过后展开“复用这次工作方法”，应先显示正在整理，再出现候选和“保存为技能”。生成速度受网络和模型影响，不以固定秒数判失败。若关闭了自动整理，可点“整理为技能”。仅“执行完成”不足以触发已验收经验提炼；提炼不应重新执行金额汇总业务。

## TC5：检查候选并保存

1. 在 TC4 的“复用这次工作方法”点击“保存为技能”。
2. 名称改为未使用的 `m5-csv-sum-demo`，检查“适用场景”和“工作方法”。
3. 方法应包含输入 CSV、`amount` 列、Decimal 求和、输出位置、检查办法和适用边界；不把本次具体金额、个人绝对路径或凭据固化为以后步骤。
4. 勾选“保存后启用”，点击“保存技能”。
5. 返回技能库，检查新技能出现，候选显示“已保存为技能”。

预期：只有整理完成且来源仍有效的候选能保存。手动保存与 TC2 的自动启用开关是不同操作。同名技能会提示产生新版本、保留旧版；不要覆盖其他业务技能。

整理失败时应显示原因和“重新整理”。重试只重新提炼，不重新执行原业务任务；原任务业务执行轮数不应增加。来源变化后的拒绝行为见附录 A2。

2. 在技能库对 `m5-csv-sum-demo` 点“更新内容”，只在适用场景末尾追加“版本验收标记 M5-V2”，保存。
3. “版本记录”应有新旧两版，新版 V2 标为当前；TC6 历史任务仍显示 V1。
4. 要核对实际加载，可新建 `M5-技能版本检查`：同员工、只读、指定该技能，要求“先调用 skill 加载技能，只说明适用场景，不执行汇总”。新任务应提供并加载 V2。

如提示“设置已保存，正在同步到员工”，等待后台重试，不重跑业务任务；如提示需要重新确认，刷新后核对员工和技能是否启用，再保存绑定。不能把技能名称显示当作加载成功。

## TC9：视频等待、交付与自动验收

此用例需要已配置的视频服务凭据和可用额度，会提交一次真实生成。也可先做下一节本地视频用例验证默认验收规则。

1. 给 M5验收员绑定 `video-production`，创建完整执行任务并指定该技能。
2. 仅在准备进行一次真实生成时提交：

> 制作一段 4 秒、16:9 的清晨海边风景短片。先调用 skill 加载 video-production，核对参数，再提交一次远端生成；等待同一个远端任务完成，下载本地视频并验证文件可播放。交付视频和简短说明，不重复提交相同生成。

3. 检查“视频制作进度”的远端编号及排队/生成/完成状态；等待时能继续聊天，也能做另一个简单任务。
4. 完成后核对下载文件与执行记录，预期独立验收自动通过。默认只确认图片/视频真实生成并交付；明确要求的时长、比例等以实际技术证据核对，不因无法观看画面而转人工。可自行打开欣赏，播放不是验收前置步骤。
5. 停止本地跟进不代表远端生成已取消；不要因等待较久重复提交。

模拟验收的远端响应与素材来自测试替身，验证的是调度、同一编号接续和交付逻辑，不能证明当前账号额度、真实服务网络、画质或收费请求已经通过。

## 本地视频补充用例：不需要方舟凭据

验证 `video-production` 的本地校验、剪辑与交付。需已有 `ffmpeg` 和 `ffprobe`，缺少时记录环境问题，不要求自动安装。使用默认设置、M5验收员、指定 `video-production`。播放前可调低音量。

任务名：`M5-本地视频技能验收`

```text
先调用 skill 加载 video-production 并阅读工具约定。本任务只做本地验证和剪辑，禁止 video_submit、video_status、video_wait、video_download，不访问远端视频服务。
1. 检查 ffmpeg 和 ffprobe 是否可用，缺少则说明并停止，不安装软件。
2. 调用 video_validate，config 为：{"prompt":"本地测试片参数校验，不提交生成","duration":4,"ratio":"16:9","resolution":"720p","generate_audio":false}。仅校验参数。
3. 在独立任务目录实际执行以下命令，生成 4 秒、1280×720、24 fps 的合成测试图和 440 Hz 测试音，不使用网络素材：
ffmpeg -hide_banner -y -f lavfi -i testsrc2=size=1280x720:rate=24 -f lavfi -i sine=frequency=440:sample_rate=48000 -t 4 -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest m5-source.mp4
4. 必须实际调用 video_edit（dry_run=false），从 m5-source.mp4 的第 1 秒开始截取 2 秒，输出 m5-edited.mp4。config 中 width=1280、height=720、fps=24；clips 使用源片实际绝对路径、start=1、duration=2；output 使用任务目录内实际绝对路径。
5. 用 ffprobe 实际检查源片与成片的时长、尺寸和音视频流。源片约 4 秒、成片约 2 秒（容差 0.2 秒），均为 1280×720，包含音视频流；运行断言检查，成功退出码为 0。
6. 交付 m5-edited.mp4 和 video-check.md，说明实际调用、检查结果以及没有远端生成。按默认规则仅验收真实成果已生成并交付，以及上述明确技术条件；不请求用户对画面或视听效果作人工确认，不声称已替用户听看。
```

预期：“执行步骤”可核对 `skill`、`video_validate`、FFmpeg 命令、实际 `video_edit` 及 `ffprobe` 检查。只有 `dry_run` 或文字承诺不算通过。打开成果能播放约 2 秒的测试图和测试音，尺寸为 1280×720。

预期显示“执行：已完成 / 验收：已验收”，原对话收到一次验收通知，无需手动点击“验收通过”。如果文件缺失、为空、快照改变或明确技术条件未通过，仍应返工或请求处理，不能仅凭文字声明验收。本地流程不要求出现远端任务编号，也不能代替 TC9。
