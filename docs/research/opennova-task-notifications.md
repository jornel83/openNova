# 任务主动汇报

总管亲自执行和员工执行的普通后台任务，都会在当前 OpenNova 对话中主动汇报：

- **已通过验收**：独立验收确认成果满足要求后，发送任务名称、结果摘要和交付文件提示。
- **需要你处理**：需要用户判断、回答问题或处理执行／验收异常时，发送原因及任务入口。关闭自动检查的任务完成后，会提示人工查看成果。

执行完成但仍在自动验收或返工时，不提前发送成功通知。内部验收、检查和技能候选整理任务不另外打扰用户。通知直接使用保存的任务与验收事实，不额外调用模型，也不会让总管自动启动新工作。

## 对话和语音

通知作为 Nova 的助手消息进入现有对话，点击“查看任务”即可打开对应任务详情。它不是用户消息，也不会自动发送一轮用户提问。后续用户可在对话中追问刚才的任务；模型会获得最近通知的只读事实，仍须按当前任务状态办理操作。

语音连接时，先保存文字，再等待没有识别、待提交输入、普通回复、播放或待处理控制指令时播报。麦克风开启时还会等人声结束，开始讲话会停止主动播报。麦克风关闭时仍可正常播报任务汇报，不要求输入设备继续提供安静音频。

麦克风开关只控制收音，播报中关闭或重新开启麦克风不会停止声音。主动汇报期间点击“停止播报”只结束本次播报，不开启麦克风、不取消后台任务、不重复播放本条通知。前台对话生成期间仍使用“停止回复”。“结束交流”会停止收音和当前播报。

每条通知的语音先持久领取，再交给 TTS，避免刷新、重连或请求重试造成重复播放。被打断、领取后的网络／播放错误都不从头重播，原对话中的文字保留。只面向通知产生时已连接的语音实例；启动或重连不会补播旧通知，等待过久也只保留文字。这是优先避免打扰和重复的交付策略，不保证用户一定听完每条通知。

## 保存和恢复

通知以任务、当前执行轮次、成果版本、分工版本和通知结果生成稳定标识。同一结果的重复事件不会生成第二条；同一成果从“需要处理”变成“已验收”是新的有效状态，可以再次汇报。

任务关闭、返工、换人或出现新一轮后，旧消息作为历史保留，标为状态已更新，并停止待播放的旧通知。升级首次启动只建立历史基线，不集中补发以前完成的任务。之后的通知与对话一起分页、持久保存，重启可恢复文字。

所有通知与任务状态继续保存在仓库外的 Bot 数据目录中。已有配置、授权、会话、记忆、成果和验收记录不迁移回仓库。

## 人工测试

按原有启动方式启动语音即可，无需另外启用通知。使用系统当前默认的麦克风和扬声器、豆包 TTS 时：

```sh
cd /你的路径/openNova
./start.command --tts-provider doubao
```

如已有旧语音进程，先用 `/quit` 退出，再启动新版。通知仅针对启动后新发生的结果；不要用重连后等待历史消息的方式测试语音。

1. **员工成功**：在对话中分配一个生成文本文件并核对内容的小任务，保持自动检查开启。预期：验收通过后，原对话自动出现一次成功消息，“查看任务”打开正确任务；无需追问进展。
2. **总管成功**：明确让总管亲自执行相同小任务。预期：同样自动验收并主动汇报。
3. **需要判断**：让员工写活动欢迎语，但要求先询问活动名称、不得猜测。预期：原对话主动提示需要补充；用文字或语音提供名称后可接续，验收成功再汇报一次。
4. **不打断**：连接语音，分配任务后继续说一段话，或让 Nova 正在回答另一问题。预期：汇报文字及时出现，语音等待空闲；不抢占当前讲话或普通回复。
5. **插话停止**：麦克风开启时，在主动汇报播到一半开始讲话，或点“停止播报”。预期：立即停止本次汇报，正常处理新输入，不从头补播；文字仍在。
6. **刷新与重连**：通知出现后刷新页面、重连语音、重启服务。预期：文字只保留一条，不补播历史通知。升级前旧任务不批量通知。
7. **旧状态**：在待处理通知出现后接续或关闭任务。预期：旧通知标明状态已更新，不再播报旧问题；新成果验收通过后出现相应的新消息。

8. **关闭麦克风仍播报**：关闭麦克风后，通过文字分配一个短任务。预期：汇报文字正常出现，语音只播一次，麦克风始终保持关闭；播报中切换麦克风不会误停声音。
9. **停止播报不改麦克风**：麦克风关闭时，主动汇报开始后点“停止播报”。预期：声音立即停止，麦克风保持关闭，任务与验收结果保留；再次刷新或开关麦克风不重播。

需要启动时保持麦克风关闭，可在原启动命令中加入 `--mic-muted`。该参数在原生音频启动前关闭输入，声音输出保持可用。
