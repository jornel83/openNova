# M5 验收：后台图片与动图任务

OpenNova 的 `image-production` 可以委派给已绑定该技能的员工。委派记录指定本轮正式操作（静态生成或编辑、GIF、本地媒体导出、抽帧审阅），并固定项目、角色及参考哈希、路径和技能版本。员工不会继承前台正在打开的文件。新成果默认落在任务工作区；只有用户指定项目内的新路径时，宿主才允许写回原项目。

## 后台执行与交付

- Seedream 用于静态图，Seedance 用于图生视频和 GIF。收到 Seedance 任务 ID 后，员工释放执行位；宿主查询该 ID，完成后在同一个员工任务和会话接续汇总。远端状态未知时保留原回执，不能通过再次工具调用、换目录或换员工重提。
- 只读任务和总管验收任务没有生成或写入工具。显式媒体任务使用独立的正式工具入口，没有额外的 Shell、文件写入、浏览器操作或旧视频生成路径。
- 成果报告只收录可信工具回执中的文件，按字节哈希核对；GIF、首帧、源 MP4 和至多必要的检查页经原有报告渠道交付。单文件 20 MiB、报告合计 64 MiB、最多 50 项。
- 调用 `gif_review` 时只将实际解码的 PNG 检查页交给视觉读取器。回执记载模型、源 GIF 哈希、实际查看帧索引及结论；抽帧不等于播放或全帧审阅。
- 暂停、取消、关闭会停止本地跟进，并保留已发生的状态。切换前台项目后，后台交付仍归原项目，前台当前文件不变。

## 回归

真实 Harness 离线匹配生产员工入口、隔离项目、真实归档执行器和本地 FFmpeg；用可控的 Ark 响应分别验证静态生图、改图、GIF、抽帧审阅和报告。回归覆盖同一个 POST 的重放去重、后台释放执行位、项目切换、分配版本变化、暂停/取消/关闭、重启后的同 ID 跟进、未知提交禁止重发，以及结果文件变化或超限时阻止归档验收。

## 实际项目验收

在隔离的真实 OpenNova 实例中，主助手经项目对话向绑定该技能的图片员工委派言昕「元气满满」动画。员工提交后释放执行位；伍宝审阅任务在等待期间运行。随后重启隔离宿主，重启前后的查询请求不同，但 Seedance 任务 ID 相同，远端生成计数为 1。原员工会话按回执接续一次。两个结果都已通过原有报告渠道交付，无缺失归档文件。

| 用例 | 实际结果 |
| --- | --- |
| 言昕「元气满满」 | 使用白色圆领无帽卫衣的确认图和已准备的文字层。成品为 640×320、4 秒、10 fps、40 帧、无限循环；40 帧固定文字校验通过。首帧 PNG 与最终 GIF 解码第 0 帧一致，保留源 MP4。正式报告收录 GIF、首帧、源视频和一个检查页，逐份核对项目原件及归档 SHA-256。 |
| 言昕抽帧与动作 | 员工调用 `gif_review` 检查 9/40 帧并记录偏差。人物、服装和文字稳定，双拳抬起后回到接近首帧的位置。人工检查约 0.3 秒开始闭眼、0.4–0.5 秒完全闭合、0.7 秒时已睁眼；有短眨眼，早于预设的 0.8 秒。没有承诺首尾逐像素一致。 |
| 伍宝「我真是服了」 | 使用 M4 已保存的 GIF，仅检查样本，没有生成请求、未修改原视频或 GIF。报告记录了检查的 9/40 帧及首尾姿态不同的风险，另附一个检查页。 |
| 任务隔离 | 端到端离线测试在等待期间切到另一个项目、选中新的静态图并重启；报告属于原项目，前台仍保留后选中的文件。 |
