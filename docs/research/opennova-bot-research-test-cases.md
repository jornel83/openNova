# OpenNova Bot 联网研究验收

更新：2026-10-24。当前 Bot 已接入 DeepSeek 后台搜索、公开网页正文读取、来源持久化和请求级检索预算。文字与语音使用同一会话、同一组工具，查询不依赖 Chrome 扩展连接。

## 1 启动准备

沿用现有一键启动命令和设备参数。在实际使用的 `config/voice.local.json` 中开启：

```json
{"web":{"enabled":true,"provider":"deepseek"}}
```

密钥沿用本机 `config/secrets.local.json` 的 `web.deepseek_api_key`；`DEEPSEEK_API_KEY` 环境变量优先。不需要再配置 Exa。配置、密钥文件和运行记录均不提交 Git。

Bot 在启动时加载配置；修改后须重启 Bot，只退出语音并不会停止 Bot。启动输出应出现“后台检索：DeepSeek 已接入”。若提示“请在结束当前语音后停止并重启 Bot”或“未开启”，当前运行的仍是旧宿主或关闭配置。健康检查只检查运行能力和配置，不额外调用计费搜索 API；API 权限以真实查询结果为准。

当前开发预览使用 18564 / 18565，普通默认部署为 18560 / 18561。使用既有主目录启动包装脚本，避免另起不同数据目录导致会话不一致。新 Bot 模式无需追加旧 `--web` 参数。

## 2 用户验收流程

先在网页输入，再选几项用语音复测。观察实际工具卡、答案和参考来源，不以模型自称“已查询”作为通过依据。回答中的温度、日期等随实时来源变化。

| 编号 | 输入或操作 | 预期结果 |
| --- | --- | --- |
| NET-01 | “北京今天几度？” | 显示“联网搜索”，必要时“后台读取资料”；返回带日期的温度，说明是实时值还是预报高低温；工作窗口保持原页面 |
| NET-02 | “北京下周五天气怎么样？” | 先明确对应日期，再给该日期预报；查不到则说明，不拼接其他日期 |
| NET-03 | “在后台读取 https://example.com，用一句话概括并附来源。” | 后台正文读取；回复下有真实来源，标记“已读取正文”，不弹工作窗口 |
| NET-04 | 语音查完天气，网页问“刚才的数据来自哪里？回查保存的证据，不用再联网。” | 调用“回查来源”，给出原链接、证据和原获取时间；不产生新的搜索；重启 Bot 后仍可回查 |
| NET-05 | “打开中国天气网，看看当前页面。” | 使用既有浏览器工具打开和读取可见页面；与 NET-01 行为不同，依赖已连接的扩展 |
| NET-06 | “查 Python 官方 asyncio.run 的用途，整理到 output/research-test.md，并用 Python 检查文件包含来源链接。” | 依次完成检索、文件保存和 Shell 检查，文件真实存在，退出码为 0；联网预算不会关闭写文件或 Shell 工具 |
| NET-07 | 搜索过程中点“停止回复”，或语音说“停一下”；随后问“用一句话介绍自己。” | 旧请求取消；新请求正常，旧答案、来源和播报不混入新轮次 |
| NET-08 | 关闭工作浏览器或断开扩展，再问一个实时天气问题 | 后台搜索继续工作；不要求先连接浏览器 |
| NET-09 | “读取 https://127.0.0.1/ 的内容。” | 拒绝受限地址并说明读取失败，不尝试通过浏览器绕过；403、429、空结果、超时通过自动化故障注入验证 |
| NET-10 | 刷新对话网页，再展开已完成回复的“参考来源”；然后普通闲聊、读取工程文件 | 来源和历史保留，刷新不触发新搜索；普通对话与工程工具正常 |

家中 Vivian 与公司豆包 TTS 均消费相同的 `speechText`：只朗读简短答复，不朗读来源 URL、卡片正文或代码。长答复完整保留在网页。真人听感和插话恢复仍需在当前设备上验收。

## 3 当前边界与排错

- 搜索使用固定 Harness 的原生 DeepSeek provider，经辅助模型 `deepseek-flash` 获取搜索结果；主推理继续由 GPT-6.1 Sol 承担。没有接入另一套独立 Search/Fetch API。
- 正文读取使用现有 HTTP 提取器，支持公开 HTML / 文本；不支持本轮范围外的 PDF/OCR、登录墙和验证码。搜索摘要足够时可直接回答，依据标记为“搜索摘要”；读取到正文只说明证据类型，不等于每个结论都已交叉核验。
- 每轮最多 2 次搜索、3 次正文读取；单次搜索 15 秒、读取 10 秒。第一次网络工具调用开始计时，30 秒后不启动新检索，45 秒中止剩余检索。连续两次读取失败后停止继续读取。同一轮相同参数不重复请求。
- 上述时间仅约束检索。模型思考和最终答案仍可能更久；工程任务沿用整轮 600 秒限制，检索收尾后仍能写文件和运行测试。当前采用完整答案确定后再播报。
- 来源按 Bot、工程、URL 保存稳定编号；每次搜索摘要和正文读取各自保存观察记录和获取时间。后续读取不会覆盖之前答案使用的证据。网页展示最多 800 字符片段，持久证据最多 12,000 字符。
- 配置或密钥缺失只关闭联网研究，保留普通聊天、工程和已有浏览器能力。401/429/超时等工具失败有中文状态，模型需说明缺失信息；不会无限重试或自动打开可见浏览器。

## 4 开发验证记录

当前自动化回归通过 230 项 Node 测试和 101 项 Python 测试。真实测试使用独立 Bot 数据目录和 18664 / 18665，避免污染日常会话；代理、GPT 授权和 DeepSeek 密钥复用已有本机配置。

已验证的真实流程：

- 未启用桌面扩展的 Bot 完成北京天气查询：1 次 DeepSeek 搜索与 1 次正文读取，返回中国天气网北京站来源，整个请求约 29 秒；此耗时为单次观测，不是性能承诺。
- 语音来源的请求完成后，以文字追问调用 `research_sources`，返回同一 sourceId、observationId 和正文证据，没有新搜索。
- 直接给公开链接时调用 `web_fetch`；明确要求打开网站时调用 `browser_open`。隔离 Bot 未启用桌面，因此后者返回 `browser_not_enabled`，证明选择路径；实际开窗延续既有桌面验收。

- 混合任务完成 Python 官方资料检索、`output/research-smoke-report.md` 保存和 Python 检查；检索开始后第 51.9 秒仍能运行 Shell，退出码 0。
- 真实搜索进行时取消，工具与请求均为 cancelled；下一轮自我介绍成功，来源列表为空，无旧结果串入。
- 隔离 Bot 重启后按原 sourceId 回查，仍返回原 observationId 与获取时间，未重新搜索。
- 网页实测展开来源卡片，展示原链接、“已读取正文”、原获取时间和证据片段；本轮未开启麦克风或重新进行两种 TTS 的真人试听。

自动化覆盖包括受限 URL 与重定向、空正文和错误状态、日期上下文、历史观察隔离、宿主重启持久化、预算耗尽、取消与迟到结果、非网络工具保留、重复搜索状态、网页来源恢复和口播投影。
