# OpenNova 原生联网接入

用户已批准本方案并要求完成 M1–M4。复用当前 DSH cccbe9cb 的 web_search、web_fetch、bash 与 Agent 循环。主模型仍为 GPT-6.1 Sol，DeepSeek 执行辅助搜索。

## 方案选择

采用原生能力加轻量产品接入。继续扩建研究中间件会重复 DSH 的执行策略；完全使用原生 UI 则无法保留当前语音和桌面体验。

## 范围

- 默认 native 模式：搜索采用 DSH provider 默认模型、maxTokens、maxUses，tool-web 搜索超时沿用内置组合的 60000ms，读取沿用 30000ms。
- 不再挂载 opennova-http、不限制每轮搜索/读取/脚本次数、不改写工具错误、不强制研究脚本与证据登记流程。
- 搜索/正文工具事件仅用于界面与来源记录；记录异常不改变模型结果。取消后迟到事件不能污染下一轮。
- 保留来源回查、旧记录、语音输出过滤、后台查询与用户主动浏览的区分、日期时区提示、已有整轮 600000ms 取消机制。
- 默认不暴露 web_request/research_exec/research_derive。普通 bash 保持既有权限。
- OPENNOVA_RESEARCH_MODE=legacy 可临时回退旧配置和实现。旧配置中的 limits 在 native 模式忽略，回退模式仍按原校验处理。
- 本次不更新 DSH 版本，不修改已有浏览器/语音功能的未提交工作。

## 验证

原生工具真实注册与响应测试；首源失败后仍可查询、原始错误保留、仅链接不变成事实、取消隔离、记录失败不影响执行；隔离 Bot 真实联网查询天气/行情/技术资料/脚本保存和来源追问。记录耗时及工具路径，实际网络不可用不能伪报通过。最后检查常用启动器、来源卡片、语音协议与回退。
