# OpenNova 通用联网研究能力补齐方案

日期：2026-10-25。状态：用户已认可会话中的修订方向；本文件为实施依据，代码与自动化已完成；真实网络结果及待完成的真人语音验收见配套验收记录。

## 目标与依据

让当前 Agent 能根据问题组合搜索、网页读取、公开接口取数、脚本处理与交叉核对。继续使用 GPT-6.1 Sol 主推理、DeepSeek 搜索、现有 Bot 持久会话和语音链路。普通查询在后台完成；用户明确要求打开或操作页面时才使用工作窗口。

本次依据是用户在 Harness 的真实会话 `session-bd6e71f5-b82c-4381-99d3-142a4be6802b`，首轮发生于北京时间 2026-10-25 00:56–00:57：一次 `web_search` 提交两个查询，返回来源链接；随后 Shell 请求新浪和腾讯报价、尝试东方财富、最后使用腾讯日 K 线核对指定日期。东方财富历史请求没有有效内容，报价请求返回 502，但包含该请求的 Shell 仍以成功退出。这条记录用于验证工具组合和结果语义，不将当时的股票数值固化为最新答案。

OpenNova 已确认的问题：新浪网页提取后只有标题；新浪报价接口需要请求头且返回 JavaScript 格式文本；搜狐响应头可能缺少编码、HTML 内声明 GB2312，现有读取器产生乱码；研究提示词限制了 Shell 补充取数；现有来源与网络预算只覆盖 `web_search/web_fetch`。

## 方案取舍

| 路线 | 取舍 | 本轮决定 |
| --- | --- | --- |
| 先制作股票专用工具 | 可以固定字段和来源，但不能覆盖其他资料研究问题 | 后续按复用频率再评估 |
| 只放开任意 Shell 联网 | 改动少，但来源、HTTP 失败和请求次数不能自动进入研究记录 | 保留现有 Shell 能力，不把它等同于受完整观测的研究通道 |
| 补齐通用读取与研究执行通道 | 模型自主选源、调用接口和处理数据，同时保留可追溯证据 | 本轮采用；用户已认可此方向 |

## 行为与边界

1. 搜索用于发现线索，已有适用接口时允许直接取数；摘要证据足够时允许直接回答，不强制固定调用顺序或每次查询两家。
2. 网页使用 `web_fetch`；需要请求头、指定编码或结构化结果的公开 GET 接口使用新增 `web_request`。请求头、编码和格式以显式参数传入，保留当前公共 URL、代理、重定向和大小限制。
3. 模型可自行编写并运行解析脚本。新增 `research_exec` 复用 Harness Shell 执行器，提供研究上下文和 HTTP 辅助命令，便于自动记录脚本内的取数；普通 `bash` 工程权限、原生取消方式和 600 秒整轮上限保持有效，无需二次确认。
4. 不再禁止 Shell 补充取数。脚本优先使用统一 HTTP 辅助命令；任意 `curl/Python` 自行联网仍属于普通 Shell 输出，不能承诺完整统计其中的 HTTP 请求，也不能自动标为“已读取接口”。没有受记录的响应时，来源说明必须保留这个证据边界。
5. HTTP 成功、正文可用和结论有依据分别记录。502 不得因 Shell 退出码为 0 成为成功来源；仅标题、空数据和截断结果不代表已经查到所需事实。
6. 数据来源按问题选择，国内问题优先匹配地区的可靠来源，允许补充和换源。回答核对对象、日期、币种、字段及复权/除息口径；最新报价不能替代任意历史日收盘价。工具提供原始事实，模型负责解释，不能宣称通用工具已自动核验所有业务含义。
7. 查询不自动打开可见浏览器。PDF/OCR、登录内容、交易操作、股票专用工具、多 Agent、替换主模型或搜索服务均不在本轮内。

## 工程细化选择

以下是为执行拆分作出的工程选择，可在实现中依据测试修正，但不能缩减上述用户认可的能力：

- 先扩展当前 Harness HTTP provider 的公开方法，复用其网络策略；不通过修改编译产物或覆写私有方法实现。对旧 `fetch({url})` 保持兼容，修改在 Harness 仓库单独提交，OpenNova 记录依赖修订与回滚方式。
- `web_request` 与 Shell HTTP 辅助命令共用宿主内的请求入口。研究脚本通过现有本机认证桥接访问该入口，绑定宿主生成的 executionId、requestId 和父 callId；结束或取消后不可继续登记结果。
- 证据增加 `api_response`、`script_output` 类型。后者是独立派生记录，不强塞进必须有 HTTP URL 的来源表，也不等同于已观察到 HTTP 响应；派生结果引用实际输入 observationId，可在网页回查原响应和执行记录。
- 首版只支持公开 GET 请求；允许 Accept、Accept-Language、Referer、User-Agent 等必要非凭据请求头。JavaScript MIME 的响应只当文本处理，不求值执行；通用 JSONP/赋值语句可交给脚本解析，不在读取器中加入站点专用解析器。
- 默认建议：每轮 2 个搜索 query（单次最多 2 个）、6 次逻辑读取（网页、接口及辅助命令合计）；单次搜索 15 秒、HTTP 读取 10 秒；60 秒后停止发起新研究调用，90 秒中止仍运行的研究调用。研究 Shell 默认 45 秒、最大 90 秒，并受剩余研究时间约束。当前 30/45 秒和 3 次读取不足以稳定容纳换源与核对，这些新值是待实测的起始配置，不是延迟承诺。
- 普通工程 Shell 不受研究预算耗尽影响；任意 Shell 内部网络请求数量标为未完整观测，不能靠正则识别命令来声称已全面控制。预算结束后 Agent 应停止新增联网取数，仍可处理已有数据和执行工程任务；对任意 bash 这是执行规则，不声称有完整网络拦截。统一入口覆盖的查询/读取精确计数，Shell 记录执行时长；重复请求只合并完全相同的有效参数，改变 Referer、编码或请求参数属于不同尝试。
- 保持当前 2 MB HTTP 响应字节上限、HTML 50 万字符上限、最终模型正文约 11,000 字符和证据片段 12,000 字符上限；完整受限响应可留在忽略 Git 的请求目录供脚本处理，截断和字符替换必须显式记录。

## 验收目标

隔离 Bot 中先验证受控响应与取消，再做真实网络验证。华润微、光迅科技、华工科技各连续查询三次，记录实际日期、来源、调用路径和耗时，不锁定某个价格；接口不可用时允许明确失败，失败、错日期或错误字段不能计为查到。至少一条非金融任务使用公开 JSON 接口并经脚本处理，一条天气查询和一条软件官方资料查询验证通用性。语音与文字共享来源，停止后旧脚本/HTTP 结果不得进入新轮次；工程开发和双窗口行为继续通过回归。
