# 后台摘要接续与错误诊断修复

用户已要求实现此前定位的两项修复。保持现有 DSH / Bot 原生摘要和换段机制，在 OpenNova 接入边界修复，不修改搜索策略、模型预算或依赖版本。

- 原生 writeNote / writeCheckpoint 使用 purpose=compaction，未被 ownRequest 的 WeakMap 标记覆盖。仅放行属于当前 Bot 现有会话分段的 compaction；其他无前台请求的调用仍按原规则拒绝。摘要只生成文本，不产生工具副作用。保留原生换段、历史、取消与重试退避。
- 在模型适配层使用 DSH 原生 LlmError 传递已清洗的错误码、HTTP 状态和服务请求编号。完成判定、Bot 持久记录、网页和终端保留这些字段，未知 SDK 文本、响应正文、令牌与用户内容不进入诊断。
- 区分网络连接、中途断流、HTTP 拒绝/限流/服务异常和真正的未完整轮次；失败后不自动重放已执行工具。
- 摘要维护日志记录阶段、会话、结果及耗时；不把摘要本身当作用户回复播报。

取舍：不关闭自动摘要，也不放开所有后台调用；不透传任意异常字符串。优先复用原生 purpose、会话归属及 LlmError。

验收：复现无前台摘要被拒绝；原生模型管线保留 403/429/网络错误且无敏感内容；验证摘要完成后原生换段与上下文延续；既有取消、语音、浏览器回归通过。先用独立 Bot 数据验证，日常服务空闲时再重启，保留会话。
