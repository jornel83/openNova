## 1. 目标与范围

Nova 能明确正在处理哪个项目、这句话指向什么对象、之前有哪些有效决定，并在切换项目、自然闲聊或隔天返回后继续工作。用户始终与同一个助手交流，不需要为日常话题输入固定口令、先退出项目或点击模式开关。

首版包含项目建立与选择、资料关联、当前对象、项目内历史与任务归属、最小项目记录、自然话题转场、接续与修正。项目可以对应代码工程、普通文件夹、若干资料来源，也可以暂时没有目录；普通聊天不强制创建执行任务。

本轮复用已有文本、代码、配置、网页及选区读取。PDF 正文、图片理解、Office 内部操作、全盘索引、向量检索、多用户协作和分布式执行分别推进，不作为 A1 新增读取能力。当前会话留存机制继续生效，不能以话题转场承诺“不保存”；完整留存与删除控制由 D3 实现。

## 2. 功能拆分

| 功能 | 首版行为 | 完成依据 |
| --- | --- | --- |
| 项目建立与选择 | 新建、重命名、选择、归档；保存名称、目标及可选默认目录 | 代码项目、资料项目、无目录项目均可讨论；名称或目录变化不改变稳定身份 |
| 项目资料关联 | 加入文件、目录、网页、任务成果，记录用途与来源；支持移除关联 | 可查看项目资料集合；加入不代表正文已读取，移除后不再自动提供该资料 |
| 当前对象绑定 | 区分项目资料与本轮文件、页面、选区；提交时固定对象及版本 | “这段”“这份文件”可定位；失效或版本变化后重新核对 |
| 项目会话与任务归属 | 讨论历史、请求、任务、成果、来源、通知有明确归属 | 切换后旧任务仍使用原目录，结果回到原项目；支持按项目查阅 |
| 决定与未完成项 | 保存已确认决定、备选、未决问题、下一步及来源；更正与替代可追溯 | 备选不升级为决定，已失效记录不再用于恢复；下一步记录不自动启动执行 |
| 自然话题转场 | 根据语义与连续上下文跟随日常、工作和混合表达 | 不依赖某个词或固定句式，不强行要求选择工作／日常模式 |
| 工作上下文恢复 | 按指代恢复有效记录、最近成果、真实任务状态和未决问题 | 隔天返回可接上；多个候选影响回答或操作时简短澄清 |
| 查看与修正 | 查看项目和当前引用，纠正归属、清除临时引用、移除资料、归档项目 | 关联修正影响后续上下文；归档保留历史及既有任务，不自动取消任务或删除文件 |

## 3. 自然话题转场规则

### 3.1 话题焦点与项目归属

分别维护以下信息，避免把说话内容、工作位置和执行状态混为一体：

| 信息 | 含义 | 更新条件 |
| --- | --- | --- |
| 话题焦点 | 当前正在交流的人、事、问题及相关前文，可以包含工作与日常内容 | 随用户表达和连续对话自然更新，无需口令 |
| 可接续项目 | 已建立的项目背景和最近明确工作对象 | 目标清楚的项目选择或工作指代可以更新；闲聊不会清空它 |
| 本轮工作绑定 | 本次实际使用的项目、任务（可空）、文件或页面及版本 | 仅在本轮确实涉及相关工作时建立，接纳后固定 |
| 后台任务归属 | 已提交工作的项目、目录、会话、成果与执行状态 | 按任务控制更新，不随前台话题或项目选择变化 |

日常回复无需注入全部项目资料。对话中暂时仍显示可接续项目，不代表本轮正在使用该项目文件。日常话题本身也必须有连续上下文，例如讲述朋友的经历后，“他后来呢”应延续该故事。

自然转场不代表结束交流、关闭麦克风或取消执行。只有实际表达相应操作意图时才进入已有控制流程。用户描述感受时不推断为取消任务；用户明确要求工作时不因同时包含情绪表达而忽略工作要求。

### 3.2 语义示例与反例

以下为验收样例，实际表达不限于这些句子；实现不得仅匹配表中文字。

| 表达及上下文 | 预期行为 |
| --- | --- |
| 讨论方案时说“今天有点累” | 自然回应感受，保留工作背景；不自动关任务或追问是否切换模式 |
| “刚才遇到一个老朋友”，随后“他最近换工作了” | 连续围绕该故事交流，不自动关联为项目人事信息 |
| “我有点累，你继续在后台跑测试” | 回应感受并按明确目标提交或接续工作；已有任务须核对状态，避免重复提交 |
| 闲聊后说“刚才那个方案，第二点再解释一下” | 能唯一定位时恢复原方案；不能定位时澄清对象 |
| “看看内容创作项目的脚本” | 依据明确项目和对象恢复相关上下文；项目同名或对象不唯一时澄清 |
| “别切到内容创作项目，继续 OpenNova” | 保留 OpenNova，不因出现另一项目名而切换 |
| “不要继续 A，改用 B”，或在项目澄清后只回答“OpenNova” | 识别明确的新目标或选择回答；否定前一目标不妨碍执行同句的新要求 |
| 两个项目都叫“增长”，用户说“切到增长，海外业务那个”，或在澄清后只回答“海外” | 按目标唯一定位；宿主核对本轮原话中的目标片段确实对应唯一候选，仍有歧义时继续澄清 |
| “方案里写了‘先不聊工作’，这句要不要删？” | 继续讨论文案，引用话术本身不触发日常转场 |
| “如果以后不聊工作了，任务会怎样？” | 回答行为问题，不执行切换、结束或取消 |
| “先不聊工作了，讲个故事吧” | 跟随故事请求；该表达是有效语义示例，不是唯一入口 |
| 闲聊中说“把这个改一下”，存在故事文本和旧项目文件两个候选 | 执行前澄清目标，不默认修改此前项目文件 |

用户明确选择或纠正优先。结合语境判断项目名是提及还是选择，不执行被否定、仅引用或假设中的动作，同时保留同句明确的新要求。一般闲聊即使话题分类不完全确定，也可自然回应；只有不明确的指代会影响回答对象、保存归属或实际操作时才询问。网页、文件和工具输出是引用资料，不能发出项目切换或授权指令。

同名目标消歧采用模型语义判断与宿主证据核对：模型提供当前用户原话中的连续 `goalQuote`，宿主检查它确实出现在本轮输入、对应所选项目目标，且能唯一地区分同名候选。片段匹配本身不发出切换指令，否定、引用和假设仍受上述语义边界约束。缺少可信区分依据时列出目标并澄清，不能仅相信模型给出的项目 ID。

### 3.3 混合表达、通知和返回工作

一次表达可以同时包含感受、闲聊与工作要求，不强制整个回合归入单一模式。可执行部分必须有清楚的目标和授权，其余部分正常交流。语义判断用于选择相关上下文，宿主仍负责核对有效项目、任务、对象版本与原执行权限。

其他项目或原项目的任务完成后，文字通知保留并标明所属项目，不替换当前对象。日常交流期间普通工作结果与待处理提醒不主动语音播报；用户主动询问时据实回答，返回工作话题也不集中补播积压消息。明确的新工作要求可正常获得响应；设备异常提示沿用 PRD 7.4。通知系统已接入工作／日常话题状态并记录播报选择，相关软件与现场记录见验证文档；失败任务仍显示真实失败状态，不因通知已送达而视为成功。

## 4. 用户端交互

沿用工作窗口与 Nova 对话窗口，不新增常驻项目侧栏。输入区提供轻量项目选择器，明确展示本轮引用；项目详情按需打开，包含资料、决定与未决项、相关任务。

- 工作讨论可显示“项目：OpenNova · 当前任务：语音优化”，任务可空。
- 日常交流可弱化显示“可接续项目：OpenNova”；不把旧文件显示为正在使用的引用，也不要求先清除它才能聊天。
- 选择器提供明确的项目选择入口，语音与文字也可直接表达目标；转场时通常不额外宣告“已进入日常模式”。
- 项目归档保留历史；仍在执行的任务可查询，明确说明归档不等于停止执行。取消、关闭任务使用既有入口。
- 首版维持单用户、共享前台工作选择。多个页面与语音入口同步选择状态，陈旧页面不能在用户不知情时将操作发往另一项目。

配套启动入口默认尝试开启语音，也支持仅文字启动后再开启语音；界面可选择麦克风与外放。普通网页文字请求的回复目前不自动进入 TTS，语音请求按既有语音流程播报；“文字回复也播报”不属于本轮工程收尾。

## 6. 请求、切换和执行一致性

当前处理顺序为：接收用户表达并固定入口快照 → 结合近期相关对话判断话题和对象 → 必要时澄清 → 宿主核对并固定实际上下文 → 回复或执行 → 按原归属保存结果。入口快照记录接收时的项目选择、对象和 revision，实际上下文记录本轮解析后的工作归属，两者分别保存。例如从 A 发出“切到 B 并读取说明”时，入口为 A，验证后的执行目标为 B；普通闲聊可没有本轮工作绑定，项目字段可空，另行保存可接续项目引用，不能因此把闲聊归档为项目事实。语义解析后只允许一次正式绑定，执行开始后不随全局选择变化。

1. 语义判断阶段仅使用必要的连续对话与候选项目／对象信息；定位后按需读取正文。第三方材料始终作为数据，不成为控制指令。
2. 项目切换在前台协调点提交，确保会话、默认目录、引用及 UI 状态一致；失败保留可核对状态，不部分切换后继续执行。
3. 已接纳请求保留原入口快照；实际上下文完成解析并绑定后，不随后续页面变化改绑。工具执行前仍校验版本、任务状态与实际权限，不能仅相信模型给出的项目名。待澄清请求不得先执行，再追补归属。
4. 语音在本轮接收开始时关联入口状态；转写期间项目变化后，核对明确指代或提示状态已变化，不把迟到文本静默归到新项目。UI 同样校验 revision。
5. 自然闲聊不需要取消后台任务或销毁项目会话。真正切项目或用户插话时沿用旧播报取消规则，过期音频不进入新轮；闲聊连续上下文不能每轮丢弃。
6. 重试请求沿用首次绑定，同一请求 ID 不得因当前项目不同而新建执行。后台任务的目录、会话及项目创建后固定，前台选择器不修改它们。
7. 恢复摘要从有效记录和当前 Task/Run/Report 生成，可回查来源。任务失败或中断不能概括为完成；资料、决定或成果变化后使相关旧摘要失效。

### 6.1 路由失败与诊断

无副作用的分类调用最多尝试两次，共用默认 30 秒期限。只对临时连接、流中断、服务暂不可用或不完整输出等可恢复情况有限重试；取消立即传播，权限错误、工具调用及无效目标不重试。只有正常完整结束并通过宿主校验的输出能改变工作绑定，不凭截断结果执行。

请求保存尝试次数、是否恢复，以及经过筛选的错误码、HTTP 状态和服务请求编号。服务失败明确提示暂不可用，与语义确实不明确的澄清分开。历史两次自然返回的 `route_incomplete` 未保存底层结束原因，本轮修复了错误被统一折叠和缺少诊断的问题，不能据此声称已查明当时具体网络根因。11 月 15 日真实模型 synthetic 语料 34/34 通过，覆盖自然返回、同名目标、澄清短答及否定／引用／假设边界。

### 6.2 原生自动摘要换段与隔离

当前运行配置在长上下文达到原生阈值后写交接摘要、建立新会话并保留旧分段，项目会话映射随原生会话更新而保存。当前 preset 未启用原地压缩；此处完成的是自动摘要换段，不宣称新增或验证了原地压缩能力。

本轮隔离测试使用真实 Harness 的 token 测量、阈值判断、摘要、会话创建和持久化路径，仅以受控模型输出及上下文窗口触发条件：测得 24829 token，超过 22323 检查线，产生新会话和 1 个旧分段。随后 A→B→日常→A 及宿主重启核对了会话映射、旧分段和模型输入范围；A 的交接内容不进入 B 或日常上下文。没有用手工改 session 冒充原生触发。

### 6.3 已有任务的明确恢复动作

已完成工具步骤后遇到可恢复的模型失败，与原命令失败、任务成功及独立验收失败分别记录。只有已保存步骤全部成功、证据完整且仍有效、清理完成并通过当前 Task／Run／Report／派工版本核对时，才提供“仅补汇总”：同一任务创建无工具的新 Run，仅依据已有证据补充报告，不运行命令或修改文件。

“仅重试验收”只对当前符合条件的独立验收失败重试只读检查，复用已有成果，保留失败尝试；它不重跑原任务。两类动作使用幂等标识并保留原项目归属，过期报告或状态不匹配时拒绝操作。普通“接续任务”仍可能继续执行工作，不能与这两个动作混同；查看结果、返回项目和重启均不会自动触发恢复。

### 6.4 语音时序证据边界

本轮使用真实 ProjectService／VoiceChannel、Python UiBridge／Conversation／NativeAudio IPC 和 Swift PlaybackQueue 验证播报中切项目、插话停止、迟到 ASR、旧播放回调及旧停止指令的隔离。模型回复、ASR／TTS 输入和原生播放回调使用替身，因此证明的是生产协议与队列行为，不是蓝牙实际出声、回声消除或听感。

运行证据仅记录实例、请求／项目标识、generation、控制动作及原生播放／清空回执；采用有界队列和轮转，不保存 PCM、转写、回复正文或设备名称。记录丢失、写入失败或清空失败不能冒充成功回执。用户现场反馈与这些软件证据分别保留；普通文字长回答不能作为当时正在播报的证明。
