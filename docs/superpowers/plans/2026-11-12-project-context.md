依据：[MVP PRD](../../product/opennova-mvp-prd.md) A1.1「资料与对象关联」、A1.2「上下文接续」及第 6 章；具体交互与范围见 [A1 项目上下文功能设计](../specs/2026-11-12-project-context-design.md)。

## 1. 交付目标与已确认规则

让 Nova 明确当前讨论涉及的项目、资料与任务，在自然闲聊、项目切换、退出重开和跨时段交流后，能够恢复正确的工作背景。

- 日常交流由用户表达的语义自然承接，不要求固定口令、模式按钮或先退出项目。「先不聊工作」是可能的表达之一，不是识别条件。
- 当前话题与项目归属分别维护。工作中聊起生活不会取消后台任务、清空项目、改变项目默认目录或任务工作目录，或把闲聊自动保存成项目决定。
- 日常话题也保留必要的连续上下文，例如讲述朋友的经历后追问「他后来呢」，应接续该故事，不能每次闲聊都创建空白上下文。
- 用户自然返回工作时，恢复其明确指向的项目与对象。存在多个可能对象且将影响读取、写入或执行时，简短澄清；不为无副作用的普通闲聊反复询问是否切换模式。
- 明确的跨项目请求或项目选择器可以改变项目归属。结合上下文区分提及与选择，不执行被否定、仅引用或假设中的动作；「不要 A，改用 B」中的新目标及澄清后只回答项目名仍正常处理。模型猜测和引用资料不能提供执行授权。
- 其他项目的任务结果保持原项目归属，不抢占当前引用或切回旧项目。闲聊期间普通工作结果保留文字入口、暂缓主动语音；返回工作不批量补播旧通知，用户主动询问时按实际结果回答。必要异常提示继续服从既有交互规则。
- 复用现有同一 Nova 身份、员工、技能和 Task / Run / Job / Report。普通交流无需新建执行任务，资料项目无需 Git 仓库，也可以暂时没有外部目录。

## 2. 现有基础和改动边界

下表保留 11 月 12 日的增量规划基线，所列 A1 连接已实现；各阶段的初版文件规划用于说明职责，实际模块拆分以当前源码为准。

| 现有模块 | 可复用能力 | A1 需补充的连接 |
| --- | --- | --- |
| `services/bot/project.mjs`、`host.mjs` | 上游工作区绑定、主 Bot、前台会话 | 解除产品仅绑定启动目录的假设；验证项目会话恢复及自然话题上下文的组合方式 |
| `requests.mjs`、`operations.mjs` | 提交时捕获工作引用、独占操作、幂等请求、持久结果 | 项目归属、上下文版本、固定执行目录及请求级快照 |
| `desktop/context.mjs`、`desktop/documents.mjs` | 页面／选区／文件引用、失效与变更提示 | 项目资料和本轮引用分离；项目切换后的恢复与旧引用失效 |
| `tasks/`、`team/task-context.mjs`、`team/reports.mjs` | 独立任务、来源可核对的指令、成果快照和接续 | 项目归属贯穿任务、子任务、验收和经验提炼；保持执行目录稳定 |
| `research/sources.mjs`、`team/notifications.mjs` | 来源回查、结果通知、语音去重 | 项目内查询、模型上下文过滤、话题相关的播报选择 |
| `memory.mjs`、团队记忆加载 | 记忆更正、失效与恢复 | 项目记录和明确跨项目个人记忆的检索范围；旧混合记忆不自动当作全局事实 |
| `web/`、`tools/voice/` | 窄对话窗口、任务面板、统一文字与语音入口 | 轻量项目选择器、上下文说明、自然转场和语音迟到结果处理 |

已新增 `services/bot/projects/`，集中管理项目注册、会话适配、语义路由、资料、记录和上下文组装，M0 已确定实际文件与接口划分。继续使用仓库外现有数据目录，不新增另一套任务执行器。

项目归属用于上下文选择、默认工作位置和结果组织。Full Access 保持既有执行契约，不能将项目资料清单称作文件系统沙箱；产品级访问撤回由 D2 衔接。D3 的留存开关和彻底删除尚需独立实现，本计划不以提示词或移除资料关联代替这些能力。

## 3. 阶段顺序与依赖

| 阶段 | 前置条件 | 交付结果 |
| --- | --- | --- |
| M0 会话与语义路由验证 | 阅读现有宿主和固定版本上游接口 | 确定可行的项目会话、日常话题连续性及工具执行前路由方案 |
| M1 项目归属底座 | M0 数据关系和会话边界明确 | 项目标识贯穿请求、任务、成果、来源、通知，兼容旧数据 |
| M2 项目切换与自然转场 | M1 完成 | 文字和语音可自然闲聊、返回工作及切换项目，不串上下文 |
| M3 资料与当前对象 | M1 完成；整体交付依赖 M2 | 项目资料清单、临时引用、版本检查、任务资料快照可用 |
| M4 决定记录与上下文恢复 | M2、M3 完成 | 跨时段恢复有效决定、真实任务状态、成果和未决事项 |
| M5 集成验收与交付 | M1–M4 完成 | 迁移、重启、多入口、语音、异常和文档状态均可核验 |

M2、M3 的独立存储或界面任务可在契约稳定后并行实现；共享的请求、宿主和任务接口修改需要协调。M1–M3 构成首轮可用交付，完成 M4–M5 后才将 A1 首版闭环标为完成。M0 已验证采用上游公开 session create/resume 接口，不改 Harness；具体取舍见验证记录。

## 4. M0：验证会话恢复与自然语义路由

本阶段涉及：`project.mjs`、`host.mjs`、`requests.mjs`、`model-gate.mjs`；按需阅读 `engine/bot/ds-bot/` 与 Harness 的实际会话接口，遵循对应目录的 AGENTS.md。验证记录已维护在 `docs/research/opennova-project-context-verification.md`。

- [x] 验证现有 `followFolder()` 的历史传递行为，以及项目专属会话创建、恢复、取消和重启恢复的可用方式；不能假设切换 cwd 就能隔离项目历史。
- [x] 验证同一 Nova 身份下项目会话与日常话题上下文如何衔接。比较独立话题片段或受控上下文投影等方案，选择能支持连续闲聊及返回工作且不混入完整其他项目历史的实现。
- [x] 定义语义路由的输入、输出及宿主校验：输入限于必要近期交流、可用项目标识和有效引用；输出表达本轮关注对象及必要的项目解析结果，不能直接授予执行权限。
- [x] 先完成无副作用的意图判断，再由宿主解析并固定执行项目、对象和允许动作。明确项目解析未完成时如何回复澄清，避免提前执行后才发现归属错误。
- [x] 建立语义样例集：同义改写、没有「工作／闲聊」关键词的转场、工作中插入生活话题、混合工作与感受、否定切换、引用中的切换文字、歧义指代以及自然返回。
- [x] 记录路由失败与服务不可用的降级：保留既有工作归属，不猜测有副作用操作的目标；普通对话保持自然回应，不能假称已经完成项目切换。
- [x] 2026-11-15 收尾：无工具、无持久模型会话的分类调用最多尝试两次，共用 30 秒期限；保留安全错误码、HTTP 状态和服务请求编号，取消、权限错误、工具调用或无效目标不重试。只有完整正常结束且通过宿主校验的结果才能绑定；服务失败明确提示暂不可用，不再统一误报成意图歧义。

验收：A→闲聊→A、A→B→A 两条路径均可复现；「他后来呢」能接续日常故事；「我不是要切到 B」及引用中的「切到 B」不会改变执行项目。测试替身用于验证契约，后续真实模型样例单独记录，不能将固定样例匹配器当作自然语言能力已验收。

## 5. M1：项目归属底座与兼容迁移

初版文件规划：`projects/store.mjs`、`projects/registry.mjs`、`projects/migration.mjs`。涉及修改：`host.mjs`、`settings.mjs`、`operations.mjs`、`requests.mjs`、`tasks/manager.mjs`、任务查询、报告、来源及通知模块。

- [x] 定义稳定项目 ID、名称、目标、可选默认目录、状态与 revision；名称和路径变化不改变项目身份。无目录项目在确有产物需求时使用明确的托管输出位置。
- [x] 提供项目创建、重命名、归档和恢复可用状态的服务/API及模型工具，沿用现有认证和操作幂等；归档保留历史和已运行任务，停止默认新建工作但不代替取消，历史仍可查询。
- [x] 给请求与相关操作增加项目归属；给 Task / Run / Report、子检查、验收及技能提炼传播来源项目。接续、重试和交接保持原项目，不因前台选择变化重新归属。
- [x] 请求接纳时冻结入口项目、引用和状态版本；语义解析与宿主核对后一次性绑定实际项目、会话、目录和对象。区分“从 A 提交、要求处理 B”与执行后改绑。普通闲聊的项目字段可空，另存可接续项目，不将闲聊按入口项目归档为事实。同一请求 ID 的网络重试返回原绑定结果，不能按新选择重新解释或重复执行。
- [x] 新任务从可信请求或显式项目操作解析工作目录；运行中任务继续使用创建时的目录和输入，不通过修改全局 `TaskManager.workspace` 改变旧任务。
- [x] 为原 OpenNova 工作空间建立默认项目。已有明确工作目录和任务来源可建立兼容关联；混合聊天、无法证明归属的历史记录保留原样或标为未归类，不让模型批量猜测。
- [x] 保留原 Bot、员工、任务和会话 ID、成果、权限及数据路径；迁移幂等，处理中断后可对账，历史任务不补跑。
- [x] 项目内历史、来源、通知和任务查询支持范围过滤；保留带明确项目名称的全部任务视图，不将跨项目概览自动注入当前模型会话。

验收：两个项目的请求、来源、成果与任务可分别查询；重启和重复迁移不复制记录；未归类历史仍可访问；旧任务仍能用原 ID 查询和接续。

## 6. M2：项目切换与自然话题转场

初版文件规划：`projects/sessions.mjs`、`projects/routing.mjs`、`projects/service.mjs`、`web/project-selector.jsx`。涉及修改：前台请求准入、宿主会话装配、控制/API、`web/app.jsx`、通知上下文、`tools/voice/` 的请求与播放生命周期；实际会话适配方案已由 M0 验证确定。

- [x] 在前台协调器中实现项目切换，只有会话、目录和状态准备成功才提交新项目；失败保留可核对的原状态。处理 Bot 状态文件与 SQLite 部分成功，避免宣称跨存储天然原子提交。
- [x] 项目选择器与自然语言选择使用统一服务，项目同名或目标不明时消歧。对话窗口使用轻量项目入口，不新增常驻项目侧栏，也不要求用户选择工作／日常模式。
- [x] 2026-11-15 收尾：同名项目按目标选择时，模型返回本轮原话中的 `goalQuote`，宿主核对该片段确实来自当前输入并唯一对应同名项目目标。支持“国内业务／海外业务”和澄清后仅回答“海外”；没有可信区分依据时仍澄清，不仅凭模型给出的项目 ID 放行。
- [x] 接入项目创建、重命名、归档、历史查看及恢复入口，语音和文字调用同一生命周期服务；对仍有任务的项目明确显示归档后任务继续，后续新工作先恢复项目可用状态。
- [x] 接入语义路由：闲聊保留当前项目作为可恢复背景，按本轮话题选择必要上下文；日常表达不产生项目决定、不改项目默认目录或后台任务 cwd、不取消后台任务。日常会话使用独立中立目录，保留同一连续日常历史。
- [x] 支持连续日常话题和自然返回工作；无选择语境的项目提及、感叹「好累」或顺便闲聊不能误触发归档、取消或跨项目切换。纠正目标和澄清后的简短回答按实际语义处理，明确工作操作仍从用户请求和有效对象解析。
- [x] 执行前由宿主验证固定项目、对象版本、请求身份和工具权限；不得只依赖模型说「已切换」。语义路由结果与工具回执分别记录。
- [x] 网页提交携带预期项目／上下文版本，旧页面在归属已变化时明确刷新或重新选择，不静默落入新项目。语音开始本轮输入时保留来源上下文；ASR 迟到、插话、切换和取消的处理与该快照关联。
- [x] 实际跨项目切换时阻止旧轮音频作为新项目回复继续输出，保留原文本和后台任务；话题转场本身不重置用户正在讲述的日常故事。
- [x] 通知始终携带原项目。闲聊时普通工作结果仅保留文字可查看状态；用户返回工作后不批量补播，主动询问则查询当前真实状态。通知正文不能自动切换项目或成为新执行指令。

验收：不使用任何固定切换话术也能工作→日常→工作；多个改写表达行为一致。A 后台任务运行时进入 B，A 结果不替换 B 的引用和会话；旧标签页、迟到转写和旧音频不串入 B。

## 7. M3：项目资料与本轮对象

初版文件规划：`projects/references.mjs`、`projects/context.mjs`、`web/project-details.jsx`。涉及修改：`desktop/context.mjs`、`desktop/documents.mjs`、`research/sources.mjs`、`desktop/tools.mjs`、`web/context-chip.jsx`、任务输入准备。

- [x] 支持文件、目录、网页、选区和任务成果的资料关联，记录用途、来源、加入方式、可读取能力和有效状态。区分长期项目资料与一次请求的临时引用。
- [x] 项目概览按需展示资料及关联任务；支持加入、移除和修正归属。移除后不再自动选入后续上下文，不伪称已删除文件或撤回 Full Access。
- [x] 每次请求固定实际对象和资料版本；读取时核对磁盘文件和页面 revision，文件更新后重新读取，失效选区不能指向新页面。沿用现有文件优先和网页后台刷新规则。
- [x] 闲聊时保留可返回的工作引用，但不将工作资料自动当作日常话题的依据；项目切换后只激活新项目适用的对象，不自动重开或覆盖用户窗口。
- [x] 为后台任务传入必要、有界、来源可核对的资料快照；区分原资料引用与固定成果副本，不能静默更新正在执行任务的输入。
- [x] 建立按项目、当前任务和显式引用优先的上下文选择；使用规模上限及截断标记，避免每轮注入所有文件和历史。

验收：同名文件在两项目中不会混用；「解释这一段」绑定发送时选区；文件 v1→v2 后不沿用旧内容执行覆盖；移除资料后不再自动注入；关联 PDF 或图片仅显示现有读取能力，不宣称已解析正文或画面。

## 8. M4：决定、未决事项与上下文恢复

初版文件规划：`projects/records.mjs`、`projects/resume.mjs`。涉及修改：项目详情、记忆接口、来源查询、任务上下文和成果查询。

- [x] 保存 A1 所需的最小项目记录：已确认决定、备选、未决问题、下一步；记录原始用户发言、任务或成果来源及有效版本。明确决定可直接登记，无需重复确认；助手建议与含糊表达不能升级为决定。
- [x] 支持更正、替代和失效传播；「只是考虑」保留备选状态，「刚才说错了」更新对应记录及受影响的恢复摘要，旧记录保留历史但不再作为当前事实。
- [x] 复用现有 Task / Run / Report 作为进度和成果事实来源，恢复时读取真实状态，不另建一套会与执行结果漂移的进度账本。
- [x] 2026-11-15 收尾：区分已完成工具步骤、后续模型汇总失败和独立验收失败。符合已保存证据与清理条件时提供“仅补汇总”，以无工具的新 Run 补充报告；“仅重试验收”复用当前成果，只重试独立只读检查。两个动作核对 Task／Run／Report／派工版本并保持项目归属，重复动作不创建重复执行，不重跑原命令；普通“接续任务”仍保留其原执行含义。
