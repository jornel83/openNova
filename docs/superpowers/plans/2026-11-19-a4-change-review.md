## OpenNova 自身工程的候选验收

1. **交付证据。** 员工在独立工作树执行无音频文字启动用例。任务报告绑定任务、执行轮次、派工版本和最终补丁的 SHA-256，保存完整候选回执、构建日志、doctor 日志、复用启动日志和登记的回归输出。冷启动、网页文字回显、默认语音入口及端口回收可在结构化回执中核对。总管在只读验收目录读取快照，用户从原对话任务卡打开相同成果。
2. **判定通过。** 已登记的复现要匹配预期退出码及输出，同项早期失败须有针对最终补丁的后续成功证据。命令与退出码全部保留。最终失败、缺少必测项、补丁不符或仍有无关失败均阻止验收。验收后补丁变化，原决定转为历史记录。启用版本需用户单独确认。
3. **复用候选验证工具。** 员工在任务工作树内调用宿主固定的验证程序。工具将实际补丁应用到独立 Git 副本，核对基线、补丁和依赖锁，从已安装的依赖复制独立副本，然后运行项目本身的 build、doctor 和启动命令。每次分配专用数据目录、令牌和本机端口。从候选网页会话提交随机校验码并核对回复后，验证热启动复用、默认语音入口和服务清理。验证期间补丁变化或任一检查失败，任务保留失败回执。

在运行这版 OpenNova 的工程项目内，可以直接对 Nova 说“请让内部员工修复无音频设备时的文字启动问题，用隔离候选版验证文字对话，完成后给我看回执”。前台提交 `background_agent_start` 并设置 `workspaceMode=code` 和 `candidateReview=true`。宿主按内容固定验证程序，员工用 `task_command` 执行，回执和日志在原任务卡打开。文字待机模式分别核对音频采集与播放已关闭、热启动使用同一 Bot 实例且取得新的待机连接。

单独测试另一个 OpenNova 副本时，可用 Node 24 在已安装依赖的 OpenNova 工程中登记测试宿主。下面的三个路径分别指向测试 Bot 的数据目录、被测项目和装好依赖的副本。已有自定义验收配置继续生效。依赖锁或相关依赖声明变化时，需要提供与候选项目匹配的依赖副本。

```sh
node scripts/candidate/install.mjs --home "/path/to/test-bot-home" --source "/path/to/test-project" --dependencies "/path/to/installed-opennova"
```

## 代码项目的开发与验收顺序

首轮由用户把任务说明复制给 Codex，再将答复或日志带回同一项目。先用现有对话、项目记录和文件引用跑通，再按实测缺口补入口行为或成果关联。交接说明可以直接是对话文字，只有用户需要正式文件时才导出 Word/PDF。

| 顺序 | Nova 应交付什么 | 第一轮如何验收 |
| --- | --- | --- |
| 1. 准备交接 | 从 A1 项目资料和 A3 已确认的决定提取目标、范围、必要约束、相关文件及版本，把任务拆成可验证的步骤，并写明希望 Codex 带回的证据。保存本轮说明的项目和版本。 | 用户说“帮我推进这个功能，交给 Codex”。得到一份可直接复制的说明，项目源码和内部编码任务数保持原状。生成说明只记录为“待交接”。用户说明已交给 Codex 时，记下该消息的来源。 |
| 2. 对照交付 | 将用户带回的改动摘要、可用的差异或提交引用、测试输出关联到相应项目和说明版本。按原验收条件分别记录已取得的证据、失败原因和待核实项。 | 同一任务含一个通过项、一个失败或缺证项。每一项都能指出依据。单凭“已全部完成”只能记录为外部自报。收到其他项目或旧说明的结果时，先核对归属。 |
| 3. 接续与归档 | 由 Nova 给出验收建议；按用户的决定记录采纳、调整范围或继续返工。返工说明沿用已通过项和已有证据，突出本轮需要补齐的部分。 | 用户带回第二轮结果后，可追到第一轮缺口和相应证据。切换项目或重启再问“还差什么”，能回到同一任务说明与最新结论。 |

## 第二批确认与冲突处理

用户可以点“确认应用”或在后续对话中说“就按这个改”。对话按本轮决定绑定项目、动作和方案。有多份候选时可用文件名、格式或卡片上的编号区分。按钮和对话共用同一次发布流程。确认会复核磁盘文件、版号及已审阅的候选，另存新版并记录原版本；重复提交返回已有结果。放弃会保存处理状态，对原文件和版本链没有写入。

确认时发现磁盘变化，原卡保留原先的对照。在能够还原手改内容时，另一张卡以最新文件为基准显示要应用的差异。用户再次确认才发布。对物资清单这类能核对原总数与各行相加结果的整数汇总，会带上用户对其他行的修改并重算。已缺失或含无法保真重建的内容，例如 Word 中的复杂格式或 PDF 批注，保留用户文件与原方案并说明原因。文件恢复后可再次核对，也可以放弃。编辑器中尚未保存的改动只能在保存后参与比较。

浏览器验收在隔离项目用真实 Chrome 点击了确认、放弃和手改后的二次确认，刷新后核对各卡状态。格式专项测试覆盖 Word 与 PDF 的手改表格、物资编号重排、长备注、PDF 批注和版本冲突。参见[手动编辑后的重建用例](../../../services/bot/tests/document-rebase.test.mjs)与[发布、重放和重启回归](../../../services/bot/tests/document-generator.test.mjs)。第三批撤销的验收记录见下文。
