# OpenNova 图片与 GIF 生成开发计划

日期：2026-11-18。**此文保留原 OpenAI 路线的设计及已完成公共基础记录。用户已决定改用火山方舟，后续以 [Seedream / Seedance 切换计划](2026-11-18-image-gif-ark-migration.md) 为准。**已验收的本地导出、保存及恢复基础继续复用，OpenAI 真实接口验证不再是当前路线的阻塞项。历史验证见 [原 M0/M1 验收记录](../../research/opennova-image-gif-m0-m1-verification.md)。

目标是让用户在 OpenNova 中自然提出“生成图片”“按参考图换衣服”“做成 GIF”“保存动画和首帧”，由正式工具完成模型调用、媒体处理、项目保存与回执。沿用三个工具和一个技能，先交付前台闭环，再接入后台任务。首批验收使用言昕“元气满满”和伍宝“我真是服了”。

## 1. 交付范围和开发决定

| 能力 | 首版范围 |
| --- | --- |
| 图片 | 新建图片、带参考图修改；PNG/JPEG/WebP；角色与风格参考；明确画幅和输出版本 |
| GIF | OpenAI 原生 GIF 路线与 OpenAI 动作帧合成路线；文字区域固定；动作、时长和循环要求 |
| 本地导出 | GIF 压缩和缩放、首帧 PNG、帧序列合成；不再次调用生成模型 |
| 项目交付 | 输出路径、版本、参考图与提示词记录、实际使用模型与路线、检查状态；默认新建文件 |
| 交互 | 沿用文件名/路径和当前文件两种入口、文字与语音请求；支持只给提示词、先静态图、已确认图直接做动画 |
| 后台 | 总管/员工按已绑定技能调用同一服务，结果归属原项目，完成后提供实际文件 |

不在首版扩展范围：图层编辑器、专业时间轴、任意视频生成、新文件上传入口、统一多供应商平台。Seedance 仍属于现有 video-production 技能；本计划的两条 GIF 生成路线均使用 OpenAI 图片模型。

模型默认候选为 `gpt-image-2.6-sunburst`，通过配置和能力表选择，M0 实测后确定正式默认值。官方编辑接口已列出参考图 GIF、2–16 帧以及 `frame_duration_ms`，但要求对应模型的 GIF preview 权限，且 GIF 不支持流式、partial images、mask 和自定义输出压缩。实现以官方接口及实际账号回执为准，不假定 SDK 类型定义已经包含所有预览字段。[官方编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit) · [GIF 生成指南](https://developers.openai.com/api/docs/guides/image-generation#generate-animated-gif-output)

原生 GIF 可用时优先评估原生路线；账号不可用时可使用项目已允许或用户明确选择的逐帧路线。`auto` 只能在已知能力与既定路线偏好内选择，不能因审核拒绝、额度不足或请求结果未知自动切换并重新付费。

## 2. 模块和工具契约

新增目录以共享实现为主，文件可按实现复杂度合并，避免建立两套图片/GIF 凭据、保存或任务系统：

```text
tools/image/
  tool.py                    固定 JSON 输入输出入口
  tool-definitions.json      三个工具的结构化契约
  providers/openai_provider.py OpenAI API 适配与能力校验（M0 已实现）
  probe.py                   离线环境检查与有预算的真实能力探针
  schema.py                  公开参数校验
  operations.py              单文件持久操作与无覆盖发布
  bundle.py                  GIF/真实首帧交付包与恢复
  gif.py                     动作帧提取、时间安排、文字合成与编码
  export.py                  首帧、缩放、压缩和媒体检查
  requirements.txt           固定直接依赖；requirements.lock.txt 锁定完整依赖
  tests/
services/bot/media/
  service.mjs                项目/请求绑定、操作状态和成果提交
  runner.mjs                 执行器调用、取消和输出限额
  spec.mjs                   工具参数、能力与回执校验
  credentials.mjs            执行器凭据读取与脱敏
skills/image-production/
  SKILL.md                   需求理解、路线选择和制作流程
  scripts/image_tool.py      仓库内固定执行器入口
  references/tool-contract.md
  references/animation.md    仅制作动画时读取
```

优先采用固定版本的官方 OpenAI Python SDK、FFmpeg 和用于媒体解码/核验的 Pillow。M0 核对 SDK 对所选模型及预览字段的支持，锁定依赖和安装方式；生产环境不依赖当前 Codex 会话的内置工具或隐藏路径。

### 公共约定

- 宿主注入 `operationId`、请求、项目、任务/run 和取消信号，模型不能自行覆盖这些身份。
- 调用时冻结规范化参数、参考文件字节及 SHA-256、角色配置版本、输出位置和执行器版本。多轮修改明确引用选中的源版本。
- 幂等键绑定一次请求中的稳定动作身份，跨工具回放、重连和接续保留；新一次“再生成”可以创建新操作，不能只用提示词哈希永久去重。供应商 request ID 用于定位请求，不当作可查询的远端任务 ID。
- 输出默认 `expectedTarget=absent`；文件已存在则返回冲突或使用明确的新版本名，不原地覆盖。文件发布复用现有二进制提交原则，不能经过文本写入接口。
- 回执包含 `status`、`operationId`、实际模型与路线、真实文件路径和哈希、尺寸/时长/帧数、分项核验结果及限制。只返回元数据与可访问文件，不把整张 Base64 塞进聊天或操作日志。
- `generation`、`fileValidation`、`animationValidation`、`visualReview` 分开记录。未做视觉检查时保持 `not_checked`。

| 工具 | 关键输入 | 主要输出 |
| --- | --- | --- |
| `image_generate` | `mode=create\|edit`、提示词、参考文件或角色配置、模型/质量、目标画幅、输出路径 | 新图片、输入/提示词/模型记录及检查回执 |
| `gif_generate` | 静态参考图、动作、`mode=auto\|native\|frames`、帧数/时间要求、目标画幅、可选固定区域、输出目录 | 最终 GIF、实际首帧 PNG、生成及检查记录 |
| `media_export` | 已有文件、`action=first_frame\|optimize_gif\|resize\|convert_image\|assemble_frames`、本地处理参数、输出路径 | 导出文件和检查回执；不得发起远端生成 |

`gif_generate` 使用 `media_export` 的同一内部实现完成导出，不由模型再拼一套 FFmpeg 命令。原生 GIF 的均匀帧延时与逐帧路线的逐帧时间数组分别表达；请求时长与交付实测时长分别保存。

`convert_image` 首版处理静态 PNG/JPEG/WebP，明确 `outputFormat`、编码质量及透明图转 JPEG 时的背景颜色；透明像素不能静默变成黑底。动态 GIF 导出静态图必须显式使用 `first_frame`，普通格式转换不悄悄丢弃动画。

## 3. 阶段安排

M1 本地公共基础已完成，M0 已完成离线验证并保留真实账号验证待办，M2–M5 尚未实施。开发可在契约冻结后并行推进固定执行器与宿主接入，主干验收按下列顺序进行。

| 阶段 | 核心工作 | 依赖 | 完成时可交付的能力 |
| --- | --- | --- | --- |
| M0 | 核对账号能力、SDK、依赖与真实调用边界 | 无 | 明确静态图与原生 GIF 能否使用，以及可选兼容路线 |
| M1 | 三工具契约、公共保存基础、本地导出 | M0 的契约决定；本地部分可并行 | 已有 GIF 可压缩、提取首帧并可靠保存 |
| M2 | OpenAI 图片生成/修改与最小前台接入 | M1 | 在 OpenNova 对话中生成图片、继续修改、拿到新版本 |
| M3 | 原生 GIF、逐帧合成和动画核验 | M1、M2 | 从确认静态图生成 GIF，并同时交付真实首帧 |
| M4 | 完整 skill、角色配置与前台预览 | M2、M3；技能打包可提前做 | 图片到 GIF 到保存的前台日常使用闭环 |
| M5 | 后台任务、归档、恢复与最终验收 | M4 | 总管/员工可按同一流程生成并交付，重启不盲目重付费 |

### M0 接口与运行环境验证

- [x] 在隔离测试配置中读取 `OPENAI_API_KEY`，或新增仓库外私有凭据文件配置；不复用 Ark key，不把凭据写入提示词或 skill。（读取器已实现；当前无已配置凭据。）
- [x] 确认图片与 GIF 请求使用的 API 路径、模型、SDK 参数和返回数据；建立按模型和账号范围区分的能力记录。模型出现在列表中不等于 GIF preview 权限已开放。（真实 SDK 本地 multipart 已验证；能力表以凭据指纹区分，不冒充已核实账号 ID。）
- [ ] 通过一次静态参考图编辑和一次小尺寸原生 GIF 的受控真实探针验证权限、返回格式与解码。调用前设置本次探针预算；不做无上限候选模型重试。
- [x] 将结果区分为支持、不支持、无权限、未验证和临时失败；网络错误不记录成永久“不支持”。无原生权限时继续图片与逐帧路线开发，保留原生路线待验收状态。
- [x] 确认 Python/SDK/Pillow/FFmpeg 的安装、版本与取消行为，补运行依赖检查；审核本地请求超时与 SDK 重试设置，保证宿主掌握重提策略。（Python 3.11.15、SDK 3.54.0、Pillow 13.0.0；请求 120 秒、重试 0，发送后中断保留 unknown，不承诺远端撤销。）

验收：保存可复核的请求参数摘要、request ID、结果文件和能力结论；无密钥输出。探针预算和实际用量可查，失败保留真实原因。

当前边界：现有 SIWC/ChatGPT OAuth 不支持图片生成，不能用于该 Images 探针；未读取或复用登录缓存。离线测试与 mock SDK 回执不能代替真实权限结论，本次真实图片/GIF API 调用数为 0。

### M1 工具契约与本地媒体基础

- [x] 实现 GIF 调色板、循环、文件体积上限和压缩预设；未达到体积目标时返回实际大小，不把模糊或裁掉主体的文件当作成功压缩。

验收：用已保存“元气满满”GIF 完成本地导出，首帧 RGB/透明度按声明与实际 GIF 第一帧一致；重复导出不调用 API，原文件未改变，交付尺寸、时长和帧数均可实测。

### M2 图片生成与前台最小闭环

- [ ] 实现 `create` 与 `edit` 两种 OpenAI 适配，参考图按角色/风格/待修改目标区分，参数受所选模型能力表约束。
- [ ] 根据请求返回解码后的图片，不把 API 返回成功当作文件保存成功；源版本、提示词、模型参数及可得的 usage/request ID 随成果记录。
- [ ] 在前台 `moduleTools → defineTool` 与策略允许列表注册正式工具，调用共享生成服务；主聊天模型与图片模型保持独立配置。
- [ ] 前台接入操作进度、取消与失败回执；生成过程使用请求冻结的项目，不受后来切换项目或当前对象影响。
- [ ] 用新文件承接换衣服、换比例等修改；只在提交成功且前台绑定仍有效时选择成果文件，不把缓存或内部配置激活为当前文件。
- [ ] 通过前台故障注入验证发送后断线、进程重启、重复调用和迟到取消；未知请求不自动重提。通用请求恢复在前台发布前完成，不能推迟到后台阶段。

验收：通过真实 OpenNova 对话完成“生成一张图 → 按参考修改为白色圆领无帽卫衣 → 保存 2:1 新版本”，而非只有 CLI 可用。角色参考、输出版本、文件路径与项目一致。

### M3 GIF 两条路线与动画核验

- [ ] 原生路线调用支持 GIF 的 Image API 编辑端点，传入静态参考图、动作与循环描述。帧数、每帧时间、生成尺寸和总像素预算按能力校验；不传不支持的 mask/stream/partial_images 参数。
- [ ] 原生调用以同步响应或实际支持的机制处理，用本地 operation 跟踪进度；不照搬 Seedance 的远端 `submit/status/download` 假设。
- [ ] 将已验证的逐帧流程提炼为正式代码：动作设计、网格/独立帧生成、切帧、时长数组、循环和编码。校验网格尺寸及边界；不规则网格返回可定位错误，不盲切交付。
- [ ] 为每次付费动作建立稳定子操作。单张动作网格是一项生成；多张逐帧请求逐项记录、复用成功结果，出现未知请求即暂停对应批次，不能整批重生成。
- [ ] 固定文字区域从已确认图片或明确版式参数提取，并作为本地合成层保存；检测与动作区域相交的风险，不在模型不支持的 GIF mask 参数上模拟此功能。
- [ ] 每次完成后解码检查多帧、实际时长、精确输出比例、循环设置和体积；文字区域逐帧比对，输出关键帧拼图并记录视觉检查状态。
- [ ] 两条路线均保留供应商原始产物与最终文件。首帧必须从最终 GIF 提取，不能用先前的静态方案图冒充。

验收：至少一条已授权路线通过真实账号与 OpenNova 调用链；原生路线无权限时标明未验收，不能算原生通过。言昕样例应看到眨眼及双拳动作，伍宝样例保留无奈神态；人物/手部/衣领无明显异常，文字稳定。编码检查与视觉结论分别保存。

## 4. 运行状态与重复计费处理

| 情况 | 处理原则 |
| --- | --- |
| 参数校验未通过、凭据不存在 | 明确失败，不发起远端生成 |
| 发送前取消 | 取消本地操作，不产生供应商调用 |
| 已收到明确的权限/额度/审核拒绝 | 保留错误与 request ID，不换模型或路线自动重提 |
| 请求已发送，连接断开或进程重启，结果无法确认 | 标记 `unknown`；本地操作去重不能冒充供应商幂等；禁止自动重新生成 |
| 模型返回字节已可靠保存，后处理失败 | 从保存的原始字节恢复本地处理，不再次生成 |
| 文件已提交，通知或界面更新失败 | 文件仍视为已保存，只补通知/绑定/回执；不因界面失败回滚成果 |
| 用户在发送后取消 | 停止本地等待/后处理并记录实际阶段；不承诺远端已停止或费用已撤销 |

重试策略在一个层面集中管理，避免 SDK、执行器与宿主各自重试。明确可恢复的失败采用有界退避；结果未知与内容审核拒绝不进入自动重提。总用量不可得时记录“未知”，不能填零费用。

## 5. 验收用例和发布条件

| 用例 | 必须核对的结果 |
| --- | --- |
| 言昕换装静态图 | 参考的是确认角色；白色圆领无帽卫衣；2:1 输出；新版本保留原文件 |
| 言昕元气满满 GIF | 角色与服装稳定、眨眼/双拳动作可见、四字准确且固定；循环、尺寸、时长实测 |
| 伍宝我真是服了 GIF | 只出现伍宝；无言昕/睡觉背景；短发中性装束及无奈动作正确 |
| 保存 GIF 与首帧 | GIF 实际多帧，PNG 与最终第一帧一致；文件可找、可打开，不能返回不存在的路径 |
| 只给提示词/只压缩/只提取首帧 | 不发生模型生成调用；已有素材不被覆盖 |
| 静态格式转换 | PNG/JPEG/WebP 可解码，透明转 JPEG 使用指定背景；无 API 调用，动态输入不被静默变成单帧 |
| 原生 GIF 无权限 | 给出能力状态，按既定选择使用逐帧路线；不伪报原生成功 |
| 审核拒绝或结果未知 | 不自动改请求、换路线或重复付费；保留清楚的操作状态 |
| 输入外部变化、目标抢先创建 | 使用冻结输入；目标冲突不覆盖；操作/输出哈希可回查 |
| 重启和重放 | 已完成结果复用，暂存产物只补本地处理，未知远端请求不重提 |
| 项目切换和后台完成 | 成果属于原请求项目，原角色参考可回查，不抢占新的前台对象 |

测试分为执行器单元测试、宿主/前台/后台离线集成测试、受控真实 API 测试、独立视觉验收。离线 fixture 不替代真实模型结果；抽帧检查范围和整个动画的播放检查分别记录。

拟新增测试位于 `tools/image/tests/` 和 `services/bot/tests/media-*.test.mjs`；正式实现后按实际文件名运行定向检查，再执行受影响模块回归及仓库要求的 `pnpm test`、`pnpm build`、`pnpm doctor`。实际结果记入独立验收报告，不以历史素材制作成功代替正式工具验收。

发布分两次：M0–M4 交付前台可用版本；M5 交付后台任务版本。若原生 GIF preview 权限未开放，发布记录写明“图片及逐帧 GIF 可用，原生 GIF 未验收”，不影响已验证能力的交付。
