# OpenNova A2 研究与学习开发计划

日期：2026-11-16；更新：2026-11-18。状态：两种文件入口的前台原生读取已实现，现支持 PDF 原页段、单次限时诊断与有限恢复；正式 `document_generate` 已接入前台，支持新建及当前项目自有成果的分版修订。生成工具在本地核验内容，PDF 自动检查几何边界，两种格式运行时均保留 `visual=not_checked`。后台文件研究已接入提交时版本冻结、隔离读写和服务重启接续。整份长文的性能边界和任意外部文档的保真编辑仍待后续工作。见[后台研究验收](../../research/opennova-a2-background-research.md)。能力基线见 [文件能力验证](../../research/opennova-file-capability-verification.md)，前台读取与本轮结果见 [A2 文件入口接入](../../research/opennova-a2-native-file-entry.md)，早期脚本探针见 [文档生成能力验证](../../research/opennova-document-generation-verification.md)，当前工具实现与验收见 [A2 文档工具接入](../../research/opennova-a2-document-tools.md)，契约见 [A2 文档生成方案](../specs/2026-11-17-a2-document-generation-design.md)。

2026-11-18 验收进展：已修复中文临时目录导致的 PDF 执行器崩溃，实际用户 Bot 以原 TC02 内容复测成功，用户确认本机 PDF 打开与重新打开补测通过。本批前台文档生成交付已无剩余手动用例；未完成的后续功能不提前交给用户验收。

## 1. 目标与已有基础

用户在项目中指定文件、网页或图片，Nova 能利用当前模型解释内容、比较资料，并在需要时保存 Markdown 笔记、Word 或 PDF 成果；后续追问可以核对原资料、版本和实际保存结果。

### 已确认的文件入口

2026-11-16 用户确认：A2 文件输入只保留以下两种方式，文字和语音使用相同规则。

| 入口 | 示例 | 对象定位 |
| --- | --- | --- |
| 直接说文件名或路径 | “读一下项目里的语音方案.pdf”；“分析 `/Users/me/Documents/实验数据.xlsx`” | 文件名优先结合当前项目目录、已关联资料和对话定位；明确路径沿用现有访问权限。能唯一定位就执行，同名歧义影响读取时简短澄清，不要求固定话术 |
| 引用当前文件 | “解释一下这份文件”；“总结当前 PDF 的第三页” | 已关联的对象沿用 Nova 本轮关联。明确指“我在 WPS 里打开的文档”时，由 macOS 桌面宿主核对发送时的文档窗口；无法定位则请用户明确目标 |

本阶段不新增文件选择器、拖拽上传、“添加资料”按钮或“从项目资料选用”作为对话输入入口。已有项目资料是按名称/路径定位的来源，A1 的资料管理与本轮使用是不同操作。底层 `input_file`/图片传递和内容快照仍用于把已定位文件交给模型，不意味着新增上传入口。

界面沿用当前对象提示，展示实际引用的文件名与必要状态，便于用户纠正。当前文件指磁盘上可定位、Nova 已关联的版本，不包含任意应用的未保存编辑。发送时固定实际文件及项目版本；项目切换或文件变化时重新核对，旧请求不静默改绑。长期加入项目资料仍遵循明确的关联操作，读取一次不自动建立长期关联。

直接复用：

- GPT 的文档理解、讲解、归纳、比较和撰写。
- 已有网页搜索、网页读取、来源观察记录及按项目回查。
- 原生 `read/write/edit/bash`、后台任务、成果报告及主动通知。
- A1 的项目归属、当前对象版本、资料关联、明确决定和会话接续。
- 本轮实测可用的原生附件通道：文字 PDF、扫描 PDF、图片和基础 DOCX/XLSX 内容读取。各格式的运行时与样本边界见验证记录。
- 现有工具链在 Node 24 下已完成：文本读写/编辑；模型编写临时脚本、调用系统 PDFKit 读取 PDF；标准库 ZIP/XML 读取及局部修改 DOCX/XLSX；系统框架生成并读回简单 PDF。无需把这些能力从零建设；脚本可行与产品入口默认稳定可用分别验收。
- 此前能力探针在同一生产模型、真实 Harness 和通用工具下，从零生成可编辑 DOCX 与中文多页 PDF：Word 独立渲染为 5 页，PDF 为 6 页，内容和外观均通过样本核验。没有复制模板、安装生成依赖或向模型提供 Codex bundled 文档库；该历史证据与后续正式工具接入验收分开记录。
- 当前正式工具已复用上述方法：Python 标准库 ZIP/OOXML 和 Swift CoreText/CoreGraphics/PDFKit 固定实现位于 `tools/documents/`，前台通过 `document_generate` 调用。结构化 JSON、真实成果、项目/请求、版本和哈希持久保存；支持 A4/Letter，仅创建不存在的目标，不要求模型重新编写生成器。

2026-11-17 用户确认的开发决定：将已验证的 Word／PDF 生成流程提炼为仓库内固定实现，通过一个 `document_generate` 工具暴露给模型。模型组织结构化内容并选择格式，Harness 调度工具，生成服务负责排版执行、核验、实际保存和回执；日常生成不再要求模型重新编写整套脚本。Markdown 继续使用现有文本工具。

本阶段复用模型的理解和写作能力，新增的是明确范围内的正式生成工具、两个格式执行器及交付流程。PDF 解析、OCR、新文档库或新的研究 Agent 框架只有在实际流程暴露明确缺口后才评估；生成工具不扩展为任意 Office 文档编辑平台。

首个开发交付聚焦 M0–M1：让用户从 OpenNova 指定文件后，直接使用已验证的附件能力，减少对模型临时编写脚本及本机解析组件的依赖。M2–M3 补齐研究成果的出处与接续，M4 为交付核验，不按模型本身已有的阅读/写作能力再拆独立研发项目。

## 2. 开发顺序

前台两种文件入口及 Word／PDF 新建、固定执行器、保存和绑定（M3.1–M3.2）沿用已验收结果。后续按以下四批开发，保留原 M0–M4 的验收归属：

1. **读取范围与稳定性（M1 前台，已验收）**：复用历史 6 页失败样本，保留单次原生读取 90 秒时限；支持真实截取连续原页段，记录超时阶段、部分结果与待续页段。没有证据表明某个固定页数一定导致超时。
2. **出处与研究笔记（M2，本批；实现及验证见[引用记录](../../research/opennova-a2-claim-evidence.md)）**：关联实际可核对的版本、位置和摘录，再复用 Markdown 写入工具保存资料比较与结论；历史笔记可回查原版本。
3. **继续修改自有成果（M3.3，第三批已验收）**：利用保存的内容规格分版修订 Word／PDF，保留旧版；磁盘外部改动阻止发布。见[功能与验收记录](../../research/opennova-a2-document-revisions.md)。
4. **后台研究与接续（M1 后台部分、M3.4、M4）**：继承固定输入与成果版本，在后台接入同一读写工具；切项目／重启不重复已完成工作，不抢占前台当前文件。

### M0：选定与当前 Harness 兼容的附件路径

- [x] 从“文件名/路径”和“当前文件”两种入口出发，沿 `/ask`、工作文件 context、请求项目绑定、Harness 消息组装及 provider，明确已定位文件如何保存版本并传给模型。
- [x] 以 Bot 数据目录内的内容寻址文件快照固定实际版本、类型、大小和项目，并复用现有操作记录存储读取结果。仅将本轮指定资料送入模型，不发送整个项目目录。
- [x] 处理当前 FileBlock 被转换为文本句柄的契约；在 OpenNova 层选择兼容接入方式，核对上游扩展点，避免仅放开类型检查而丢失实际附件。
- [x] 隔离真实 OpenNova 宿主已打通 PDF/扫描 PDF/PNG/DOCX/XLSX，PDF 当前文件追问与重启后的 XLSX 当前文件读取通过。沿用当前授权与 Node 24；不是独立 SDK 成功代替入口验收。网络恢复后，PNG/扫描 PDF 修正问题复验与重启后的历史追问均已通过；原始失败记录保留，详见本轮验收。

完成标准：通过 OpenNova 实际请求链路，模型读到附件中的随机标记与内容；历史保存、项目归属和工具调用保持正确。

已选接入方式：`document_read` 在工具内调用同一 `gpt-6.1-sol` 的 `input_file/input_image`，主会话接收持久化的读取文本与来源，不将上游 FileBlock 伪装成可直传附件。主 provider 继续如实声明文本输入，不改上游 Harness。每次原生读取是独立附件请求；PDF 模型请求超时后可以缩小范围再试一次。取消与本轮信号一致；历史回放复用已完成的工具结果。

### M1：把已验证格式接入日常入口

- [x] 实现文件名/路径的语义定位与已关联当前文件的指代解析，复用项目资料和当前对象；同名时澄清、缺失时说明，成功定位后按需读取。
- [x] 沿用当前对象提示展示实际文件和读取状态；不增加文件选择、拖拽上传或项目资料选用入口。
- [x] 按 M0 选定路线在只读工具内按真实 MIME 传送文件/图片；主对话通过现有文本工具结果投影与历史机制接续，读取文本被标为不可信资料，不能授权执行。无需错误地扩大主 provider 的模态声明。
- [x] 文字/扫描 PDF、PNG、基础 DOCX/XLSX 均通过生产 Node 24 的实际 `/ask → document_read` 读取，来源字节哈希与项目匹配。格式边界及补测过程如实记录，不等于全部格式认证。
- [x] 前台文字与语音请求采用相同冻结项目/当前文件绑定；语音入口协议已验证，未新增声学验收。
- [x] 后台文件研究支持两个文件入口，提交时固定文件字节和来源，在后台通过 `document_read` 阅读原版本。
- [x] 明确模型附件 20 MiB（前台按页段读取的本地 PDF 原件可至 64 MiB）、缺失/类型不符/版本变化/取消/超时/原生通道失败与部分可读状态；加密或损坏由原生读取器报告 unreadable/partial 或安全错误，不承诺准确区分所有损坏原因。
- [x] 保留原 6 页 PDF 的失败记录，按原件和原问题复测整份原生读取；本轮基线 47.853 秒、`partial`，未重现历史 90 秒超时。实现分阶段耗时诊断和模型超时后的有限恢复；不宣称已定位历史单次超时根因或可保证全文读取。
- [x] 实现按原 PDF 的连续物理页提取真实附件，显示总页数、读取范围与待续页段；保持原件身份和版本，临时页段不激活为当前文件。
- [x] 6 页历史样本在真实 `/ask` 通过两个入口：指定文件读第 5–6 页，当前文件读第 1 页；13 个内容字段匹配，出站附件实际为正确的 2 页和 1 页，原件不变。见[读取专项验证](../../research/opennova-a2-native-file-entry.md)。
- [ ] 继续验证复杂长文和章节定位；只指定章节或问题而无可靠起止页时，不猜测页码，也不把缩短问题当作附件裁剪。
- [ ] 加密、严重损坏、长文复杂排版与公开 URL 下载的真实样本边界验证。

完成标准：用户通过文件名/路径，或“这份文件”等当前对象指代，自然提出解释和比较要求，无需自行运行解析命令或上传文件；不能读取时有真实原因，不能把文件已关联/已打开当作正文已读。

### M2：补齐引用与资料版本

- [x] 生成工具核对所引用文件的 sourceId/哈希及网页 observationId 与本轮项目证据，保存来源身份和版本；通用 sources.locator 仍不算已核实，逐结论依据使用独立核验的 claims。
- [x] 扩展现有 source/observation，关联文件身份、内容版本、实际读取范围和证据摘录，保持同一 URL/文件的不同版本可区分。
- [x] PDF 显示物理页和对应摘录，网页保留当次正文观察；Word 使用正文顶层非空段落，Excel 使用工作表及单元格，不捏造页码。
- [x] 关键结论可以回查已读证据；仅有搜索摘要、部分读取或内容无法确认时明确标注。
- [x] 资料被外部修改、删除或移除项目关联后，旧笔记保留原版本依据，新请求重新核对。

完成标准：用户追问“这句话依据哪里”，能看到对应文件/网页、版本和可核对位置；模型给出的页码仍需质量验收，通道读取成功本身不是引用正确性保证。

### M3：研究成果保存与项目接续

- [x] 此前验证通用工具加模型脚本可从零生成 Word／PDF；正式工具接入在下列条目单独记录，不能混用两轮证据。

#### M3.1：正式工具契约和公共执行基础

- [x] 实现 `document_generate`：`format=docx|pdf`、`specPath`、`outputPath` 和可省略的 `expectedTarget=absent`；项目/请求绑定由宿主注入。结构化内容只作数据，不执行任意脚本或 OOXML；第四批已接入后台研究任务绑定。
- [x] 固定版本化 spec，覆盖标题、章节、段落、列表、表格、版式选项和来源引用，保存输入快照/哈希并限制资源；汇总行列数错误给出 `document_summary_columns_mismatch` 及字段详情，不静默截断。
- [x] 新增生成服务、子进程超时/取消和二进制成果提交；临时生成、基础核验后发布受控字节副本，原子无覆盖提交，避开 ≤64 KiB 的文本写入接口。
- [x] 覆盖 callId 幂等、参数冲突、取消提交竞态、目标抢先创建、输入变化和中断对账；已有成功结果不因重试或重启重复生成/覆盖。
- [x] 正式生成链路使用本地内容/结构核验，不调用会改变当前文件的预览读取；内部 spec 和临时文件不激活对象。生成、内容、自动几何与视觉检查分别返回，两种格式的运行时视觉状态均为 `not_checked`。
- [ ] 预期版本/哈希保护下的替换与修改前版本保留；当前仅接受 absent，任何已有目标均返回冲突，不支持替换参数。
- [ ] 将内部读取不激活对象推广至其他原生视觉/语义核验调用；现有普通 `document_read` 仍遵循用户读取后选择文件的行为。

当前完成范围：新建服务契约和保存流程通过定向自动测试，取消/冲突不覆盖原文件，正式生成内部核验不改变用户对象；旧版不作替换；自有成果的分版修订见 M3.3。

#### M3.2：固定 Word／PDF 执行器与前台工具接入

- [x] 将 Python 标准库 ZIP/OOXML 流程提炼到正式工具目录，去掉样本硬编码，支持可编辑标题层级、列表、表格、页眉及页码域，核验 XML/关系/顺序内容。
- [x] 封装 Swift CoreText/CoreGraphics PDF 生成与 PDFKit 本地读回，支持中文、自然分页、跨页表头、末行/汇总行和可检索文字，检查页数及字符边界；超高表格行、超长页眉显式失败。
- [x] 探测固定 Python/Swift 命令及脚本，实际执行器确认运行条件，PDF 检查中文字体；失败不阻塞文字聊天。未借用 Codex bundled 依赖或验证目录文件，命令存在不等于完整编译环境预检。
- [x] 通过前台 `moduleTools → defineTool` 和策略允许列表暴露工具。模型负责内容与格式，工具调用仓库内固定执行器；后台注册见 M3.4。
- [x] 固定执行器与 Harness 离线集成覆盖不同内容、中文/特殊字符、长段落、长单元格、跨页表格和 A4/Letter；结构/内容成功不冒充 Word 渲染或逐页视觉通过。
- [x] 真实 `/ask` 请求调用 `document_generate` 生成 Word 和多页 PDF，复测确认实际文件/哈希、磁盘版本和最终对象正确。独立逐页检查覆盖真实复测 PDF，以及 Word 拆行修复后由复测冻结 spec 重生成的最终样本；该重生成属于执行器复验，不算第三次真实模型请求。

软件接入、真实模型验收和修复后执行器复验分开记录；最终证据及原始失败保留在 [本轮工具接入记录](../../research/opennova-a2-document-tools.md)。独立样本视觉通过不改变工具回执中的 `visual=not_checked`。

完成标准：前台 Agent 直接调用正式生成工具产出两种文件，用户无需运行命令，模型无需编写生成器；工具返回真实成果和分项检查状态。

#### M3.3：来源关联、交付与修改

- [x] 前台保存约定路径、项目/请求、spec 和成果版本，并检查来源身份/哈希/observationId；逐结论摘录使用本批核验结果，后台成果按任务、项目和分配版本归属。
- [x] 与 M2 对接可靠定位和逐结论依据；在研究成果中区分原文事实、模型推断、用户决定和待核实问题。
- [x] 新建提交成功且请求绑定仍有效时选择最终 Word/PDF；用户已切换项目或对象时不抢占新选择，不自动加入长期项目资料。
- [x] 展示可找到的实际文件并复用 `document_open`，明确生成、内容已核验、版式未核验与打开请求已发送等不同结果。普通讨论不强制后台任务，Markdown 沿用文本工具。
- [x] 继续修改前核对磁盘现状，复用版本检查与成果快照。自有生成成果可根据保存的 spec 生成新版本；外部修改产生冲突时不能用旧 spec 静默覆盖，任意 Office 保真编辑仍属后续范围。

完成标准：读资料→组织内容→调用生成工具→保存/找到/打开→核对出处→继续修改闭环通过，最终当前文件、项目、来源和成果版本一致。
